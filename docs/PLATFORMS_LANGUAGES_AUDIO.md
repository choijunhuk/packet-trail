# Windows·macOS·Linux, 다국어, OST 제작 계획

상태: 출시 목표와 검증 계약. 현재 설치 파일·번역 리소스·음악 파일은 제작하지 않았다.

## 1. 세 OS를 같은 제품으로 유지한다

Godot 한 프로젝트와 공통 콘텐츠를 사용한다. 플랫폼별로 게임 규칙을 달리하지 않는다. 공통 설정·단축키 처리와 실제 입력·저장·패키징 차이만 분리한다. [Godot export](https://docs.godotengine.org/en/stable/tutorials/export/exporting_projects.html)

| 대상 | 초기 패키지 목표 | 필수 확인 |
|---|---|---|
| Windows x86_64 | 압축 실행 폴더, 후속 설치 패키지 | 깨끗한 계정 실행, 저장 경로, 창/전체 화면, IME, 압축 해제 경로 |
| macOS | Apple Silicon·Intel 지원 여부를 빌드 시 확인한 앱 패키지 | 실제 아키텍처 실행, IME, 권한, 서명·공증·Gatekeeper, 업데이트 |
| Linux x86_64 | 실행 파일+데이터 패키지 | 실행 권한, 실제 배포판/그래픽 환경, 폰트·IME, 저장·대소문자 |

macOS 개발 실행과 외부 배포 가능은 다른 주장이다. 서명·공증을 하지 않은 빌드가 로컬에서 열렸다는 이유로 일반 사용자 배포를 완료했다고 표시하지 않는다. [macOS export](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_macos.html)

Linux는 ‘모든 배포판’ 호환을 약속하지 않는다. 첫 지원 환경을 정하고 실제 기동·입력·저장을 확인한다. 다른 CPU 아키텍처는 추가 지원 대상으로 분리한다. Windows 설치 프로그램·Linux AppImage/패키지 방식은 압축판 검증 뒤 선택한다.

## 2. 빌드와 수동 검증을 분리한다

CI는 데이터 검증·헤드리스 테스트·export를 실행하고 각 산출물에 버전·commit·SHA256을 붙인다. 다운로드한 최종 파일과 테스트한 파일의 해시가 같아야 한다. CI가 만든다는 사실은 실제 OS에서 조작했다는 뜻이 아니다.

| 검증 단계 | 자동화 가능 | 실제 OS 필요 |
|---|---|---|
| 데이터·목표·다중 해법 재생 | 헤드리스 | 최종 재미는 별도 |
| export·파일 구조·체크섬 | CI | 실행·패키지 차단 확인 |
| 3D 렌더·OS UI·창 포커스 | 일부 자동 캡처 | 그래픽/창 환경별 smoke |
| 한글·일본어·중국어 조합 | 일부 입력 fixture | 각 OS 실제 IME |
| 저장·강제 종료·업데이트 | 자동 실패 주입 가능 | 플랫폼별 파일 교체·권한 |
| 오디오 장치·볼륨·백그라운드 | 일부 상태 검사 | 실제 청취·출력 장치 |

출시표는 플랫폼별 `빌드/실행/입력/저장/오디오/배포`를 따로 표시한다. 하나가 실패하면 해당 플랫폼을 완료로 묶지 않는다.

## 3. 다국어 범위

| 단계 | 목표 |
|---|---|
| 첫 기술 검증 | 한국어 UI와 영어 명령, CJK 입력·fallback 확인 |
| 시제품·MVP | 한국어·영어 전체 경로 |
| 1.0 목표 | 한국어 `ko`, 영어 `en`, 일본어 `ja`, 중국어 간체 `zh_Hans`, 스페인어 `es`, 독일어 `de` |

6개 언어는 목표다. 번역·검수·폰트·레이아웃·플레이 검증을 통과한 것만 지원 목록에 공개한다. 번역이 준비되지 않은 언어는 완료 표시하지 않는다. 번역 인력·분량이 병목이면 1.0 날짜와 언어 팩 순서를 다시 산정한다.

Godot 번역 리소스를 사용하고, 기본 초안은 CSV 또는 PO 파이프라인 하나로 고정한다. 다수형·맥락이 필요한 서사 확장을 고려해 **PO를 기본 권고**한다. 별도 번역 프레임워크를 만들지 않는다. [Godot internationalization](https://docs.godotengine.org/en/stable/tutorials/i18n/internationalizing_games.html)

### 번역할 것

UI·도움말·오류·힌트·메일·채팅·게시판·가상 사이트·복습·후일담·오디오 설명·접근성 라벨을 번역 키로 둔다. 코드에 문장을 이어 붙이거나 이미지에 텍스트를 구워 넣지 않는다. 변수는 이름 있는 자리표시자로 치환하고 문법 순서를 번역자가 바꿀 수 있게 한다.

### 번역하지 않을 것

Linux 명령·옵션·가상 호스트 ID·경로·URL·JSON 필드·세션 ID·저장 키는 안정적으로 유지한다. 사용자에게 보이는 설명만 바꾼다. 언어를 바꿔도 저장·미션 판정·정답 경로가 바뀌면 안 된다.

### 폰트와 레이아웃

Latin 고정폭과 CJK fallback을 묶고 출처·라이선스·버전을 기록한다. Noto 계열 등 후보를 검토하되 이번에 실제 도입·배포한 것으로 쓰지 않는다. 라이선스가 확인된 파일만 저장소에 넣는다.

긴 독일어·스페인어, CJK 줄바꿈, 한국어 조사, 숫자·주소·고정폭 정렬을 검증한다. 가짜 확장 문구로 30~50% 길이 증가를 검사하고 실제 번역으로 다시 확인한다. 메시지 키 누락은 CI에서 실패로 처리한다. 원문 대체 fallback이 있다고 번역 완료로 계산하지 않는다.

## 4. OST 방향

오리지널 전자음악·앰비언트 중심으로 제안한다. 텍스트를 읽고 비교하는 시간이 길어 보컬·강한 드럼·급격한 음량 변화가 집중을 해칠 수 있다. 조사 상태에서는 반복 가능한 얇은 편성, 현장 모드에서는 리듬·저음층을 더한다.

| 큐 | 용도 | 초기 길이 목표 | 반복·전환 |
|---|---|---|---|
| A01 Signal Home | 메뉴·작업실 | 2~3분 | 부드러운 loop |
| A02 First Connection | 첫 사건·안내 | 2~3분 | 설명을 가리지 않는 편성 |
| A03 Hidden Route | 조사·브라우징 | 3~4분 | 긴 반복에서 피로도 확인 |
| A04 Packet Flow | 도구 비교·진전 | 3~4분 | A03과 1~2초 crossfade |
| A05 Raised Alert | 선택형 긴장 상태 | 2~3분 | 경보 상태에 따라 진입·복귀 |
| A06 Broken Pattern | 반전·증거 발견 | 2~3분 | 스포일러가 되는 과도한 정답음 피하기 |
| A07 Clear Channel | 해결·엔딩 | 3~4분 | 엔딩 편집용과 loop 구분 |

시제품은 A01·A03·A05의 짧은 스케치로 방향을 검증한다. 1.0의 7곡·약 17~24분은 제작 목표이며 현재 OST 파일은 없다. 여러 시간의 플레이는 loop·상태 전환으로 대응한다. 곡 수를 늘리기 전에 실제로 장시간 들어본다.

## 5. 오디오 구현

`Master/Music/SFX/UI/Ambience` 버스를 분리한다. 음악은 두 플레이어로 단순 crossfade하고 방·조사·경보·회고 상태에 연결한다. 복잡한 외부 미들웨어나 박자 단위 적응형 시스템은 첫 버전에 필요하지 않다. [Godot audio buses](https://docs.godotengine.org/en/stable/tutorials/audio/audio_buses.html)

키보드·도구·알림 소리는 독립적으로 줄일 수 있게 한다. 같은 경보를 겹쳐 재생하지 않는다. 중요한 상태는 화면 텍스트로도 알린다. 음악 음소거·창 비활성 시 정책·장치 변경·볼륨 복원·게임 정지를 확인한다.

압축 배포 파일과 무손실 제작 원본을 구분한다. loop 경계 클릭, 체감 음량 차이, 긴장 큐 반복 피로도, 세 OS 재생을 청취 검수한다. 정확한 포맷·압축률·음량 기준은 첫 스케치 테스트 뒤 고정한다.

## 6. 음악 제작·권리·AI의 역할

작곡·외주·라이선스 음원·생성 도구 중 실제 제작 경로는 별도 선택한다. 기존 게임의 OST를 복제하거나 음원을 추출해 쓰지 않는다. 곡마다 출처·제작자·권리·배포 가능 범위·원본·버전·크레딧을 기록한다.

AI는 향후 무드·큐 구조·피드백 정리에 활용할 수 있다. 현재 음악 생성 서비스 호출·구매·외주 발주·Claude 추가 호출은 하지 않는다. 유효한 사용 권리와 실제 품질을 확인한 결과만 배포한다.
