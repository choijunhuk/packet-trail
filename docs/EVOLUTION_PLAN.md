# 발전 방향: 실제 판단을 하는 해킹 게임

기준은1.2.1 소스/실제화면 감사다. 단순히 도구·사건 수를 늘리기보다 관찰→가설→행동→검증→결과가 연결되는 경험을 우선한다. 모든 서버와 명령은 게임 내부 모형이다.

## 이번1.3의 제작 범위

- 종합 도전3사건을 독립 콘텐츠/저장 슬롯으로 추가한다. 기존3편44사건과 새3사건의 검증을 분리한다.
- 접수 서비스의 정상 업무/접근 통제/인증 제한, 실제 배포 파일/통지 범위, 관측 출처/시각 오차/초기 오판 반박을 각각 결합한다. 시간 제한이나 반복 입력을 난이도로 대신하지 않는다.
- 각 사건의 두 해법은 실제 정책·endpoint·파일 또는 관측 출처가 다르다. 같은 해법의 입력 순서만 바꾼 것을 독립 경로로 계산하지 않는다.
- 도구 화면을 관찰·행동·결과 작업대로 바꾼다. 빈 보조 기록을 기본 화면에서 줄이되 모든 공개 필드/행 상세를 열어볼 수 있어야 한다.
- 처음 의뢰와 저장 알림의 중복 강조를 줄이고 현재 목표에서 사건 보드로 바로 이동하게 한다.

## 다음 확장의 우선순위

| 축 | 현재 근거와 발전 방향 | 수락 기준 |
|---|---|---|
| 실제성 | 서비스의 정상 업무를 유지하면서 보안 조치, 서버 발급 세션과 공유 주소 구분, 관측 시각의 불확실성처럼 실제 논리를 사용 | 성공/거절의 원인이 모델 상태와 일치, 반례로 주장을 뒤집을 수 있음 |
| 게임성 | 선택이 다른 상태·실제 결과를 만들고 잘못된 접근에서 복구할 수 있어야 함 | 선택별 관측 가능한 차이, 두 유효 경로, 무조건 전체 차단/쓰기 해법 불가 |
| 디테일 | 각 화면의 현재 계정·대상·요청과 과거 결과를 일관되게 유지 | 탭/창/저장 복원 뒤 주체 일치, stale 결과 명시, 초안 보존 |
| 시각성 | 해킹 도구의 정보 계층과 명확한 실행 결과를 먼저 개선하고 사이트 유형은 실제 저작 데이터와 연결 | 작은 화면·큰 글씨·다국어에서 조작 가능, 가짜 기록/신뢰 배지 없음 |
| 학습 | 첫20분의 막힘을 실제 초보/숙련 플레이로 확인하고 도움을 필요한 순간에 제공 | 다른 유효 해법을 막지 않음, 힌트 안 쓴 기술을 숙달로 처리하지 않음 |
| 서사 | 현재 선택 상태와 맞는 인물 반응/후일담을 늘림 | 선택하지 않은 조치를 했다고 고정 출력하지 않음 |

우선 보류: 실제OS/실인터넷 실행, 거대한3D도시, 동시멀티플레이, 새공격기법 이름만 늘리는 확장. 사용자 목표에 비해 비용·검증 범위를 크게 늘린다. 모바일 분석·리버싱 선택 사건은 기존 UI/증거/복구 구조를 재사용하며 새로운 추론을 줄 수 있을 때 추가한다.

## 난이도와 지원

가이드/표준/자율은 도움량이다. 실제 도전은 별도 저작된 사건의 복합 제약으로 제공한다. 기존 캠페인의 규칙을 설정파일 값으로 소급 변경하지 않는다. 범용 난이도를 나중에 도입한다면 게임 시작 때 고정한ruleset과 저장 버전/원본 보존이 선행돼야 한다.8~12시간과 재미·체감 난도는 자동검사로 입증할 수 없으며 사람 플레이 측정이 필요하다.

## 구현 모델과 전환

이번 제품 구현은 요청에 따라Sol6.1 high/xhigh를 사용한다. Astra는 통합/검증을 맡는다. 같은 제품 결함을 두 차례 수정해도 재현되거나 저장/모델 경계를 만족할 설계가 없다는 근거가 있으면, 실패 로그와 소유 범위를 고정한 뒤 해당 구현만 Astra로 전환한다. 한 번의 정상적인 RED→GREEN을 모델 실패로 간주하지 않는다.
