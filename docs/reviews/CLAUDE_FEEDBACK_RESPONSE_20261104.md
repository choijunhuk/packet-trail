# Claude 피드백 검토·개정 결정

입력은 [Claude 피드백 원문](CLAUDE_FEEDBACK_20261104.md)이다. 원문은 보존하고 아래 판단에 따라 기획을 개정한다. 이번 작업은 문서 개정이며 게임 구현 착수 요청으로 확대하지 않는다.

## 개정 계획

1. 가칭 **심야접속**, 침투의 손맛과 이야기가 먼저인 해킹 시뮬레이터로 제품 설명·첫 미션·피드백 연출을 맞춘다. 이름과 A안 선택은 전달된 피드백에 기록된 결정을 반영한 것이며, 저장소 ID `packet-trail`은 유지한다.
2. 스토리 속 안내·기존 기술 재사용·숙련자의 대안 해법을 유지하고, 학습 평가·전이 문제는 선택 복습으로 내린다.
3. P0는 개발 OS의 2D 데스크톱·터미널·IME, P1은 M01 하나의 잠입·자료 회수·후일담·저장 왕복으로 제한한다. P2부터 3미션·3D 회색상자·ko/en 시험·세 OS 초기 smoke를 추가한다.
4. 기술 설계에 P1 최소 계약과 P2/MVP 이후 확장 조건을 구분한다. 저장 손실 방지·현재 상태 판정·가상 실행 경계는 첫 버전부터 유지한다.
5. 상태·미구현 설명은 README로 모으고 검증 기록에는 검증 범위를 남긴다. 기존 상세 계약과 사용자 출시 목표는 보존한다.
6. 현재 소스·전역 규칙을 확인해 모델/Claude 협업/향후 merge gate 기록을 고친다. 문서 정적 검사와 작성자와 분리된 검토 후 커밋·푸시한다.

## 유지할 출시 목표

PC 설치형 Godot 권고, 작은 3D 작업실+가상 OS, Windows/macOS/Linux, 한국어·영어를 거친 다국어 확대, 오리지널 OST, 메인24+선택4의 빠른 첫회8시간/탐색12시간, 특정 도구를 강요하지 않는 다중 해법을 유지한다. 수량·상세 제작량은 시제품 실측으로 조정한다.

## 추가 제공된 Hacknet 구조 자료

사용자 정적 보고서의 가상 Computer/파일·등록 명령·목표·저장 분리는 P1 최소 구조를 뒷받침한다. 먼저 실행 파일 식별 정보만 대조했고, 이후 설치 파일을 추가로 열지 않고 제공 설명을 참고한다. 보고서의 외부 이메일/CEF 관찰과 새 게임의 내부 실행 경계를 구분한다. [패키지 참고](../references/HACKNET_PACKAGE_NOTES_20261104.md)

## 후속 사용자 질문: 캐릭터 외형·프롬프트

당초 문서에는 인물의 역할만 있었고 외형·이미지 규격·생성 프롬프트는 없었다. 후속 질문에 따라 [캐릭터 아트 설계](../CHARACTER_ART.md)를 추가했다. 세미리얼2D 초상화, 서윤/도윤과 추가2인 후보, 표정4종, 공통 그림체와 인물별 완성 프롬프트·참조/버전/검수 기준을 제안한다. 실제 생성·정본 선택·이미지 가독성 검수는 수행하지 않았다. 이 추가는 Claude 원문의 지적으로 꾸미지 않는다.

## 검증 기준

README·PROJECT_PLAN·DESIGN·CURRICULUM의 첫 경험과 기본 위험/피드백이 일치해야 한다. P0/P1 완료 조건에는 3D·6개 언어·OST·다중 OS 완주·고급 증거/작업 큐를 넣지 않는다. 이후 도입 구간과 최종 목표는 별도로 남긴다. 원문 피드백 무변경, 미션 ID·선수 관계·JSON·상대 링크, 실제 모델 기록, 독립 검토와 Git 전달을 확인한다.

## 개정 결과

제품·화면·미션·기술·로드맵·인수인계·협업 문서를 같은 방향으로 맞췄다. 원문 피드백은 수정하지 않았다. 중복 현재 상태 설명은 README로 모으고 과거 검토와 실제 실행 경계는 각 기록에 남겼다.

독립 검토의 잔여 3개 지적을 보완한 뒤 문서 READY, 추가 캐릭터 문서는 텍스트 기획 READY를 받았다. 최신 정적 검사와 검증 한계는 `docs/PLANNING_VALIDATION.md`에 기록한다. 새 게임 코드·이미지·음악 생성이나 Claude 호출로 작업 범위를 늘리지 않았다.
