# Claude Code 2차 피드백 (2026-11-04)

검토자: Claude Code (`claude-opus-5-5`). 대상: 커밋 `9a47769`의 기획 문서 전체와 사용자가 대화로 제공한 Hacknet 정적 분석 보고서.
이 문서는 의견이다. 사용자 승인·테스트 통과·공식 근거로 취급하지 않는다. Hacknet 관련 사실은 사용자 보고서의 정적 분석 기준이며, 이 검토에서 원작을 열거나 실행하지 않았다.

## 1. 요약

1차 피드백의 큰 지적(방향, P0 범위, 무거운 계약, gate 위치)은 모두 반영됐다. 이제 문서는 구현을 시작할 만큼 충분하다.

남은 문제는 세 가지다.

1. **M01에 "거부 → 돌파 → 접근" 순간이 없다.** 기획이 첫 재미로 정한 장면인데, M01은 메일로 받은 계정으로 바로 로그인한다.
2. **Hacknet에서 드러난 버그 유형 세 가지가 계약에 빠져 있다.** 빈 목표, 모르는 goal 종류, 저장 왕복 누락이다.
3. **문서를 더 고치는 것은 이제 수익이 작다.** 다음 단계는 P0 코드다.

## 3. 새 문제와 최소 수정안

### 3.1 M01에 접근을 "얻는" 순간이 없다 (가장 중요)

- **위치:** `PROJECT_PLAN.md:9`는 첫 재미를 "접속 거부를 넘어 접근권을 얻고"로 정한다. 그런데 `docs/CURRICULUM.md:63`은 접속 단서를 메일로 주고, `docs/ARCHITECTURE.md:222`는 "의뢰에 제공된 프리셋 계정"으로 접속한다고 적는다.
- **재현 조건:** M01 흐름을 그대로 따라가면 플레이어는 받은 계정으로 `ssh` → `ls` → `cat` → 회수 순서로 진행한다. 거부당하는 단계가 없다.
- **영향:** P1의 판정 질문 "접근의 성취가 생기는가"를 시험할 장면이 없다. 경보도 반복 `AUTH_DENIED`에서만 오르므로(`DESIGN.md` §7 P1 정책) M01에서는 경보 피드백을 시험할 기회가 거의 없다.
- **참고:** Hacknet은 첫 튜토리얼에서 connect → probe → PortHack → `scp`로 곧바로 침투 장면을 준다(보고서 §5.4).
- **최소 수정안:** 포트 개념은 M03까지 미뤄도 된다. 권한만으로 장면을 만든다.
  1. 메일의 계정은 `guest` 수준이다. 공개 폴더만 보이고 보호 폴더는 `Permission denied`가 난다.
  2. 공개 폴더에 남은 파일(인수인계 메모 등)에서 야간 정비 계정이나 보관 경로 단서를 찾는다.
  3. 두 번째 로그인에 성공하면 프롬프트의 사용자가 바뀌고 ACCESS 피드백이 나온다. 보호 폴더가 열린다.
  4. 단서 없이 보호 폴더를 반복해서 두드리면 경보가 1~2까지 오른다. 이렇게 하면 경보도 P1에서 시험할 수 있다.

### 3.2 빈 목표 목록과 모르는 goal 종류를 거절하는 규칙이 없다

- **위치:** `docs/ROADMAP_AND_QA.md:60`의 `validate_content.gd` 범위는 "필수 필드/자료형·중복/없는 ID·가상 경로"다. `docs/ARCHITECTURE.md:139`는 goal kind를 유한하게 등록한다고만 적는다.
- **재현 조건(Hacknet):** 보고서 §7.2 기준으로 Hacknet은 목표가 비어 있으면 완료(true)로 판정하고, 지원하지 않는 goal type은 오류 없이 건너뛴다. 오타 하나로 목표가 전부 빠지면 미션이 즉시 완료될 수 있다.
- **영향:** 같은 실수가 M01.json에서 나면 테스트 없이 "완료" 상태가 된다. 거짓 완료는 `SENSITIVE_PATHS`(`godot/data/missions/**`)에 해당한다.
- **최소 수정안:** 콘텐츠 검사 항목에 두 줄을 추가한다. "goals가 비어 있으면 거절", "등록되지 않은 goal kind면 거절". headless 테스트에 각각 실패 fixture를 하나씩 둔다.

### 3.3 "저장 왕복"의 판정 기준이 없다

- **위치:** `docs/ROADMAP_AND_QA.md:50`, `docs/ARCHITECTURE.md:362`는 round-trip을 검사한다고만 적는다.
- **재현 조건(Hacknet):** 보고서 §8.5 기준으로 Hacknet은 저장할 때 `activeCheck`를 쓰고 불러올 때 `activeChack`(오타)을 찾는다. `ShouldIgnoreSenderVerification`과 `willSendEmail`은 저장에 들어가지 않는다. 화면상 정상 동작이어도 일부 설정이 조용히 사라질 수 있다.
- **영향:** "저장 후 불러오기가 오류 없이 끝남"만 확인하면 같은 유형의 누락을 놓친다.
- **최소 수정안:** P1 완료 조건을 "`load(save(S))`가 S와 deep-equal"로 적는다. 비교는 WorldState 전체와 완료·회수 자료·후일담 상태를 포함한다. 필드를 추가할 때마다 테스트를 고칠 필요 없이 누락이 잡힌다.

### 3.4 같은 단계표가 9개 파일에 있다

- **위치:** P0~P2 단계 설명(3D 회색상자·ko/en·3OS 시점)이 README, PROJECT_PLAN, DESIGN, ROADMAP, ARCHITECTURE, CURRICULUM, HANDOFF, CHARACTER_ART, PRODUCTION_RESEARCH에 반복된다.
- **영향:** 단계를 하나 바꾸면 9곳을 고쳐야 하고, 하나라도 놓치면 문서끼리 어긋난다. 부정문도 많다. `ARCHITECTURE.md`는 429줄에 "않는다·아니다·금지" 계열이 127개다. 결정보다 "하지 않을 것"을 찾기가 더 쉽다.
- **최소 수정안:** 단계표는 `ROADMAP_AND_QA.md` 한 곳에만 둔다. 다른 문서는 "단계는 ROADMAP 참고" 한 줄로 바꾼다. `PROJECT_PLAN.md` §13과 `HANDOFF.md`의 "이번 작업에서 새 Claude 호출은 하지 않았다" 같은 세션 기록은 `AI_WORKFLOW.md`로 옮긴다.

### 3.5 검증 기록이 저장소 밖 파일을 가리킨다

- **위치:** `docs/PLANNING_VALIDATION.md`는 검사기 `.omx/artifacts/check-feedback-docs.py`를 근거로 든다. `.gitignore`가 `.omx/`를 제외하므로 이 파일은 저장소에 없다.
- **영향:** 다른 사람이나 다른 기계에서 "링크 97개 누락 0"을 다시 확인할 수 없다.
- **최소 수정안:** 검사기를 `tools/check_docs.py`로 옮겨 추적하거나, 기록에 "로컬 전용, 재현 불가"라고 적는다.

### 3.6 작은 항목

- **회수 명령 이름이 없다.** M01 카드(`CURRICULUM.md:65`)는 "목록·읽기·회수 도움말"이라고만 적는다. Hacknet은 `scp`로 원격 파일을 로컬 폴더에 복사한다. M01 명세에 실제 명령 이름(예: `scp <파일>` → 로컬 `~/archive`)을 정한다.
- **목표 자료의 판정 키를 정한다.** M01 전이 질문은 "같은 이름의 사본이 둘"인 상황을 다룬다. Hacknet의 `filedownload`는 이름이 아니라 파일 내용으로 비교한다(보고서 §7.2). M01 목표는 파일명이 아니라 콘텐츠에 선언한 `record_id`로 판정하고, 웹 보관 경로(경로 B)로 얻은 사본도 같은 `record_id`를 갖게 한다. 이름만 같은 미끼 파일은 다른 `record_id`를 준다.
- **명령 대소문자·별칭 규칙을 한 곳에 정한다.** Hacknet은 명령마다 대소문자 처리가 다르다(`connect`는 소문자화, `cd`·`rm`·별칭 `nmap`은 원문 비교, 보고서 §5.2). `command_registry.gd`가 별칭과 대소문자 규칙을 한 번만 정의하게 적는다. Linux식이라면 "명령은 대소문자 구별"이 단순하다.
- **콘텐츠 값과 실행값을 같게 둔다.** Hacknet XML의 `portsForCrack val=3`은 내부에서 `val-1`로 저장된다(보고서 §5.4). 콘텐츠 숫자를 실행 시 변환하지 않는다는 규칙을 콘텐츠 계약에 한 줄 넣는다.

## 4. Hacknet 분석 활용

### 4.1 이미 같은 결론인 것 (유지)

| Hacknet 관찰 (보고서) | 심야접속 계약 |
|---|---|
| 포트 목록·열린 포트·관리자 권한이 별도 상태 (§4) | 열린 포트는 서비스 존재일 뿐 (`ARCHITECTURE.md` §4) |
| `ExecuteProgram`의 bool이 성공 여부와 무관 (§5.2) | Action 결과는 `ok`/`error_code`로 반환 (§3) |
| 명령을 백그라운드 스레드로 실행, 예외를 출력 없이 소비 (§5.1) | P1은 메인 스레드 순차 처리, 실패는 명시적 오류 (§3) |
| `delay` 목표가 벽시계 기준 (§7.2) | wall-clock 타이머 없음, 논리 상태로 판정 |
| "Session Saved" 표시가 모든 저장 성공을 보장하지 않음 (§8.1) | 저장 실패를 화면에 알림, tmp→검증→bak→교체 (§10) |
| 세이브가 원본 미션 파일 경로에 의존 (§8.2) | 같은 구조(`mission_id` + 가변 상태). P1은 배포 세이브가 없으므로 지금은 문제 아님. MVP의 `content_hash` 도입 조건과 맞음 |

이 항목들은 Hacknet 구조 노트(`docs/references/HACKNET_PACKAGE_NOTES_20261104.md`)에 "우리 계약과 일치" 근거로 짧게 추가할 만하다.

### 4.2 가져올 것

- **도구를 게임 안 파일로 얻는다.** Hacknet은 새 도구가 서버에서 복사해 오는 `bin/*.exe` 파일이다(보고서 §6.3, §9.4). 도구 획득 자체가 침투 결과물이라 보상감이 크다. 우리 `tool_unlocks`도 "서버에서 회수한 자료로 도구가 생긴다"로 표현하면 M01의 회수 동작이 도구 획득으로 이어진다. 구현 비용은 거의 같다.
- **위 3.2, 3.3, 3.6의 검사 항목.** Hacknet이 실제로 가진 함정이므로 첫 테스트 목록에 바로 넣을 수 있다.
- **완료 처리 순서를 명시한다.** Hacknet은 분기 초기화 → 다음 미션 로드 → 종료 함수 → 저장 순서다(보고서 §7.4). 우리 문서는 "목표 평가 → UI 갱신 / 자동저장"까지만 적는다. 완료 효과(서윤 답장, 다음 노드 공개)를 목표를 만족시킨 Action과 같은 커밋에 넣고 그 뒤에 저장한다고 적으면, 완료와 저장 사이에 종료돼도 불러올 때 상태가 어긋나지 않는다.

### 4.3 가져오지 않을 것

- 공백 한 칸 기준 split, 명령별로 다른 대소문자 처리, 미등록 명령을 실행 파일로 넘기는 fallback.
- 메일 답장 문자열로 완료하는 방식(`getstring`). 우리는 상태 기반 판정을 이미 택했다.
- 첫 성공 분기만 인정하는 분기 구조. 우리는 대안 경로를 같은 목표로 판정한다.

### 4.4 보고서를 저장소에 넣을지

보고서 원문에는 로컬 경로(`/Users/...`)와 원작 예제 XML 발췌가 있다. 기존 노트는 원작 XML을 저장소에 복사하지 않는다고 정했다. 원문은 저장소 밖에 두고, 위 4.1·4.2의 결론만 기존 노트에 요약하는 편이 이 규칙과 맞다.

## 5. 추천 순서

1. M01 카드에 3.1의 거부→돌파 장면, 회수 명령 이름, `record_id` 판정을 넣는다. CURRICULUM 한 곳만 고친다.
2. P0를 시작한다: `godot/project.godot`, 데스크톱, 터미널 하나, 한글 IME 확인.
3. P1 첫 코드와 함께 `tools/gate.sh`를 만들고 3.2, 3.3 검사를 첫 테스트로 넣는다.
4. 3.4, 3.5의 문서 정리는 코드 작업 사이에 한 번에 처리한다. 이것 때문에 P0를 늦추지 않는다.

## 6. 이번 검토 기록

- 저장소의 추적 문서 전체를 읽고 1차 피드백과 대조했다. `grep`으로 단계표 중복, 부정문 수, 검증 산출물의 추적 여부, 빈 목표·goal 종류·round-trip 관련 문구를 확인했다.
- Hacknet 보고서는 사용자가 대화에 붙여 넣은 원문만 사용했다. 원작 설치본을 열거나 실행하지 않았다.
- 게임 코드·기존 문서·커밋은 변경하지 않았다. 이 파일 하나만 추가했다.
