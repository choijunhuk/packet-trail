# 개발 순서·파일 소유·완료 조건·검증 계획

이번 저장소는 기획 단계다. 아래 경로는 **예정 경로**이며 아직 게임 코드가 존재한다는 뜻이 아니다. 선행 조건을 통과한 뒤 다음 단계로 간다. 세부 데이터·명령 계약은 [ARCHITECTURE.md](ARCHITECTURE.md)를 따른다.

## P0. 엔진·입력·창·3D 전환 기술 검증

예상 3~5 작업일의 가설. 권고 엔진 Godot 4+GDScript와 같은 버전의 export template를 고정한다. 개발자가 사용하는 OS에서 먼저 확인하고 다른 두 OS의 초기 export smoke도 수행해 늦은 포팅 실패를 줄인다.

예정 파일: `godot/project.godot`, `godot/scenes/room/workroom.tscn`, `godot/scenes/desktop/desktop.tscn`, `godot/scenes/apps/terminal_window.tscn`, `godot/scenes/apps/browser_window.tscn`, `godot/scripts/ui/desktop_controller.gd`.

완료 조건:

- 한 방에서 컴퓨터를 사용하고 전체 화면 OS로 들어갔다가 돌아온다.
- 터미널 2개·브라우저·도구 창의 이동·크기·포커스·최소화·재열기가 된다.
- 한글 IME·붙여넣기·선택·키보드 전환·1280×720/고배율을 확인한다.
- ko/en 문자열 전환·CJK fallback·음악 버스 설정을 작게 검증한다.
- 세 OS의 패키지 생성과 실제 실행 여부를 따로 기록한다.

실패 시 콘텐츠를 늘리지 않는다. 내장 Window로 필요한 UX가 안 나오면 Control 창틀로 전환하고 비교 근거를 남긴다. 엔진 재검토는 재현 가능한 결함과 구현 비용을 근거로 한다.

## P1. 가상 월드와 한 사건을 끝까지 연결

예정 파일: `godot/scripts/core/world_state.gd`, `network_model.gd`, `virtual_fs.gd`, `session_manager.gd`, `command_parser.gd`, `command_registry.gd`, `mission_evaluator.gd`, `save_store.gd`, `godot/data/hosts/`, `sites/`, `missions/`, `godot/tests/headless/run_all.gd`.

메일→가상 사이트→대상 발견→터미널·도구 조사→유효한 증거→사건 완료→후일담→저장/재개를 한 번 구현한다. 먼저 실제 사건 하나가 작동하게 하고, 그 사건이 쓰는 데이터·조건 타입만 공통화한다.

완료 조건:

- 같은 초기 상태·행동이면 같은 결과가 나온다.
- 명령·GUI 도구·브라우저가 같은 상태·권한·네트워크 결과를 보여준다.
- 열린 포트에 무조건 쉘을 주지 않고 서비스별 조건을 검사한다.
- 미도달·필터링·로그인 실패·인가 거절이 구분된다.
- 실패한 행동은 일부 상태만 바꾸지 않는다.
- 손상 저장·쓰기 실패·재시작에서 기존 진행을 조용히 덮어쓰지 않는다.

## P2. 3미션 수직 시제품

M01·M05·M09를 프리셋으로 제공한다. 정식 캠페인 선수 미션 완료를 위조하지 않고 필요한 자료·상태만 시제품 컨텍스트로 제공한다. 목표 시간은 25~40분이다.

예정 파일: `godot/data/missions/M01.json`, `M05.json`, `M09.json`, `godot/data/tutorials/`, `godot/data/tools/`, `godot/tests/fixtures/solutions/`, `wrong_paths/`, `godot/tools/validate_content.gd`.

완료 조건:

- 3개 사건이 브라우저·터미널·도구·증거·후일담을 포함해 완주 가능하다.
- 새로운 도구를 안내받은 뒤 기존 도구와 다시 조합한다.
- 안내를 건너뛰고 다른 유효한 경로로 해결해도 캠페인이 진행한다.
- 새 기술을 쓰지 않은 완료는 해당 기술 `not_assessed`로 남긴다.
- 가능한 사건에 의미 있는 대안 해법을 테스트한다. 단순 순서 변경은 별도 해법으로 세지 않는다.
- 잘못된 요청·명령·권한·재시작·저장 복구·창 닫기가 진행을 막지 않는다.

입문자 약 5명으로 막힘과 페이싱을 관찰한다. 숙련자에게는 정해진 풀이를 알려주지 않고 자유 경로가 막히는지 본다. 표본이 작으므로 교육 효과의 통계적 입증으로 쓰지 않는다.

## P3. MVP 10미션

M01~M10, 캠페인 선택·도구 도움말·복습·설정·ko/en을 연결한다. 목표 90~150분. 도구가 늘어날 때 코어가 미션 ID별 분기문으로 비대해지는지 확인한다.

첫 두 사건의 실제 제작·검수·번역·테스트 시간을 기록해 전체 공수를 재산정한다. 3OS 실제 smoke, 설치·업데이트·저장 보존, 오디오 3큐, 텍스트 확장 검증을 수행한다.

완료 조건은 10개 사건의 정답·대표 오답·대안 경로 재생, 목표 상태·정상 기능 유지, 사용자 플레이의 주요 막힘 해결, ko/en 누락 0, 플랫폼별 상태 공개다. 빌드가 생성됐다고 학습·재미가 통과한 것으로 표시하지 않는다.

## P4. 1.0 캠페인 메인24+선택4

네트워크 침투·웹·서버/시스템·계정·로그/패킷을 연결하고 6장 메인24개와 선택4개를 완성한다. [PACING_AND_STORY.md](PACING_AND_STORY.md)의 480분+240분 예산으로 사건 깊이·선택 탐색을 검증한다. 메인 목표는 8~12시간. 각 장 마지막에는 새 도구 이름을 먼저 알려주지 않는 종합 사건을 둔다.

선택 후보 R01 리버싱·P01 포너블은 MVP 이후 별도 작은 모델 검증을 통과한 경우에만 제작량에 추가한다. 모바일·AD·클라우드·무선/IoT는 이번 메인 필수 범위가 아니다. [분야 판단](DOMAIN_SCOPE.md)

1.0 목표에는 6개 언어 검수와 OST 7큐를 포함하되 완성 여부를 각각 추적한다. 번역·음악·플랫폼 검증이 빠진 상태에서 ‘전체 완성’이라고 하지 않는다.

## P5. 출시·패키징·후속

Windows/macOS/Linux의 다운로드 파일, 설치·실행·입력·저장·오디오·업데이트 증거를 모은다. 플랫폼별 서명·배포 채널·가격·등급·권리 확인은 출시 준비 단계에서 결정한다. 현재 공개·유료 출시를 확정하지 않았다.

최종 산출물에는 버전·commit·SHA256, 지원 OS/CPU·언어, 알려진 문제, 세이브 호환성, 크레딧·자산 권리를 포함한다. 스토어 등록을 별도 작업으로 본다.

## 1. 테스트 범위

| 층 | 중요한 사례 | 실패 기준 |
|---|---|---|
| 파서 | 빈 인자·따옴표·미완성 인용·명령별 옵션 arity·긴 입력 | 토큰 손실·옵션 오해·명령 상속 속성 접근 |
| VFS | 절대/상대 경로·`..`·파일/디렉터리·부모 권한·삭제 | 경로에 따른 권한 우회·잘못된 파일 손실 |
| 네트워크 | public/internal 경로·방화벽·출발 세션·포트 상태 | 전역 주소를 알면 내부망 직통 |

| 세션 | 터미널별 cwd·계정·exit·브라우저 세션 | 창 간 권한·세션 유출 |
| 취약 모델 | 의도한 조건·잘못된 조건·수정·정상 기능 | 정답 문자열 외 경로 실패·만능 exploit |
| 목표 | 초기 미달·유효한 복수 해법·제약 위반 | 특정 도구/명령·pin·튜토리얼 강제 |

첫 구현부터 모든 미래 기능을 테스트하지 않는다. 해당 단계의 비단순 로직과 실패 비용이 큰 경계부터 보호한다. 새 미션은 초기 미충족·완주 경로·대표 오답·대안 경로·재시작의 작은 fixture를 남긴다.

## 2. 검증 명령과 정직한 상태 표시

다음은 **구현 후 마련할 명령 계약**이다. 지금 실행 가능한 테스트가 이미 있다는 뜻이 아니다.

```sh
godot --headless --path godot --script res://tools/validate_content.gd
godot --headless --path godot --script res://tests/headless/run_all.gd
godot --headless --path godot --export-release "Windows Desktop" builds/windows/PacketTrail.exe
```

테스트 러너는 실패 시 명시적 비영 종료 코드를 반환해야 한다. 단순 assert 로그만 보고 CI 성공으로 처리하지 않는다. 콘텐츠 미정의·끊긴 참조·알 수 없는 조건 타입은 조용히 건너뛰지 않는다.

검증 증거에는 `PASS/FAIL/NOT_RUN`, 명령·환경·대상 commit·산출물·한계를 쓴다. 헤드리스 검사는 UI 조작이나 실제 IME를 대체하지 않는다. 게임이 없는 현재 단계에서 lint/typecheck/export/플레이 결과는 `NOT_RUN`이다.

## 3. 계획 공수와 중단 조건

1인+AI, 주당 20~30시간, 기존 엔진 경험을 가정한다. 기술·UI 1~2주, 시제품 추가 2~4주, MVP 추가 4~6주, 캠페인·언어·OST·8~12시간 캠페인·품질 추가 11~18주를 초기 가설로 둔다. **총 18~30주, 약 360~900시간**이며 테스터·번역·외주·스토어 작업으로 달라진다. R01/P01은 별도 산정한다.

첫 미션 제작량으로 재산정하기 전 약속 날짜로 쓰지 않는다. 시제품이 설명 없이 진행되지 않으면 미션 수를 늘리지 않는다. 대부분의 시간이 운영체제·에디터·기술 데모 제작으로 새면 핵심 루프로 돌아간다.

## 4. 현재 기획 저장소의 검증 대상

현재는 Markdown 상대 링크, JSON 예시 문법, 미션 ID·단계 수량·학습/캠페인 분리, 사용자 최신 방향 반영, 비공개 정보·실행 원문 제외, Git 원격 일치를 확인한다. 이 검증을 게임 테스트 통과로 표기하지 않는다.
