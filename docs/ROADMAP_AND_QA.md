# 심야접속(가칭) 개발 순서·완료 조건·검증 계획

현재 구현·검증 상태는 [README 현재 상태](../README.md#현재-상태)를 따른다. 저장소 ID는 `packet-trail`이다. 단계별 최소 계약을 먼저 구현하고 세부 상태·명령 경계는 [ARCHITECTURE.md](ARCHITECTURE.md)를 따른다.

## 단계별 필수 범위

## P0. 개발 OS의 2D 데스크톱·터미널·입력

Godot 4+GDScript와 같은 버전의 export template를 고정한다. P0는 개발 OS 한 곳에서 핵심 글자 입력이 잘 되는지 확인한다. 이식·장식보다 2D desktop과 터미널 한 개부터 검증한다.

실험 파일 후보: `godot/project.godot`, `godot/scenes/desktop.tscn`, `godot/scenes/apps/terminal_window.tscn`, `godot/scripts/apps/desktop_controller.gd`. LineEdit 입력과 RichTextLabel 출력만으로 시작한다.

완료 조건:

- 한글 IME 조합·Enter 제출·붙여넣기·선택/복사·포커스 복원을 확인한다.
- 창 이동·최소화·닫기/재열기 뒤 입력이 유실되거나 뒤 창으로 새지 않는다.
- 개발 화면의 기본 해상도와 고배율에서 입력줄·출력이 잘리고 복원 불가능해지지 않는다.
- 어떤 입력/포커스 문제가 재현됐고 어떤 선택으로 해결했는지 짧은 증거를 남긴다.

임베드 Window로 필요한 입력 UX를 얻지 못하면 Control 창틀로 전환해 비교한다. 3D·완제품 브라우저·두 터미널·다국어 실물·OST·세 OS 완주는 P0/P1 필수 조건이 아니다.
P0 실험을 제품용 게임 소스로 처음 편입할 때는 아래 P1의 첫 소스/gate 규칙을 함께 적용한다.

## P1. M01 ‘첫 번째 야간 의뢰’ 한 사건

익명 연락처 서윤이 삭제될 인계 기록 사본의 회수를 요청한다. 제한된 가상 야간보관소 세션 등 지원 경로로 연결하고 파일을 찾아 지정 허구자료를 회수한다. 의뢰인의 반응·다음 단서가 도착하고 저장/재개 뒤에도 결과가 유지돼야 한다. 상세 목표·대사는 [CURRICULUM.md](CURRICULUM.md)를 따른다.

예정 파일은 한 사건이 쓰는 `godot/scripts/core/`의 `world_state.gd`, `action_dispatcher.gd`, `command_parser.gd`, `command_registry.gd`, `virtual_fs.gd`, 최소 세션/목표 평가/저장 코드와 `godot/data/hosts/`, `godot/data/missions/M01.json`이다. 가상 웹 사본 경로를 구현해도 내부 route 부분만 추가하고 브라우저 완제품을 선행 조건으로 삼지 않는다.
첫 루프는 의뢰→가상 연결/파일 탐색→자료 회수→의뢰인 반응/다음 단서→save round-trip이다. 패치·보고서 시험·지정 도구·증거 pin은 필수 완료 조건이 아니다.

완료 조건:

- 등록 명령만 파싱/실행하고 지원 밖 명령/옵션은 명확한 안내를 준다. 같은 초기 상태·행동은 같은 결과를 낸다.
- 가상 파일·계정·세션·회수 자료는 단일 WorldState를 사용한다. UI가 정답 플래그를 직접 쓰지 않는다.
- 상태 변경은 validate→변경안→일괄 적용이다. 파싱/참조 오류와 변경 실패는 부분 상태를 남기지 않는다.
- 목표와 대상/정상 서비스 제약은 현재 상태에서 재평가한다. 과거 성공 관찰만으로 현재 불충족을 통과시키지 않는다.
- 연속 읽기·새 관찰·무관한 로그 때문에 기존 관찰을 폐기하지 않는다. 세부 증거 버전 벡터는 만들지 않는다.
- 창 닫기/재열기는 동일 세션·cwd를 보존한다. `exit`·명시적 로그아웃만 해당 연결/인증을 바꾼다.
- 가상 host/경로가 실제 OS 파일·프로세스·네트워크로 이어지지 않는다. 콘텐츠 로딩/저장 어댑터는 별도로 확인한다.
- 로컬 오타·읽기·IME는 risk가 없고 반복 AUTH_DENIED/서비스 접근 거부만 해당 경로의 Action 경보를 높인다. 임계 뒤에도 유효 세션·다른 허용 경로·체크포인트 재시도를 보존한다. 수치는 [DESIGN](../DESIGN.md)을 따른다.
- 안내/복습을 건너뛰어도 진행한다. 학습 여부를 캠페인 통과와 분리하며 전체 LearningState·분석 루브릭을 요구하지 않는다.
- save_version 일치, tmp 쓰기→재읽기 검증→정상 bak 보존→교체, round-trip과 손상/쓰기 실패의 명시적 오류·원본 보존을 확인한다.
- 의뢰인 반응·다음 단서가 실제 회수 결과를 읽는다. UI progress는 동기 처리한 결과의 연출이며 pending_jobs·wall-clock 사망 타이머를 만들지 않는다.
- 첫 제품 소스와 실제 `tools/gate.sh` 및 아래 검사를 함께 만든다. gate/검사 누락·실패가 있으면 소스 변경을 merge하지 않는다.

### 첫 게임 소스와 함께 만드는 merge gate

`tools/gate.sh`는 콘텐츠 검증→실제 headless runner→지원 경계 검사를 실행하고 어느 실패도 비영 종료로 전달한다. 엔진/runner/검사 파일 누락을 skip이나 성공으로 바꾸지 않는다.

| P1 gate 항목 | 함께 구현할 검사 |
|---|---|
| 콘텐츠 | `godot/tools/validate_content.gd`: M01 부분집합의 필수 필드/자료형·중복/없는 ID·가상 경로 |
| 실제 runner | `godot/tests/headless/run_all.gd`: 실제 M01 코어의 초기 미달→회수/후일담, 실패 원자성·현재 목표·관찰 보존·창 수명·학습 비강제 |
| 저장 실패 | 정상 tmp/bak 왕복, 손상 JSON·버전 불일치·쓰기/교체 실패 주입에서 원본/정상본 보존 |
| 지원 경계 | 미등록 명령·실제 OS 경로·외부 origin 입력 거절의 동적 사례와 실제 I/O 호출 경로 검토 |
| 정적 보조 | 외부 실행/통신 API 위치와 명령 dispatch 경로 검사; 플레이어 문자열이 실행 API로 연결되지 않음 |

외부 API 이름 grep만으로 안전을 증명했다고 하지 않는다. 정적 검사·경계 입력의 동적 결과·실제 I/O 어댑터/호출 경로 검토를 함께 사용한다. 콘텐츠 읽기/사용자 저장의 정상 I/O와 가상 명령 경로를 구분한다.
이번 문서 개정에서는 게임 코드나 빈 gate를 만들지 않는다. 실제 코어 없이 성공을 반환하는 스크립트는 완료 조건을 만족하지 못한다.

## P2. 3미션 수직 시제품과 표현 위험 확인

M01·M05·M09를 프리셋으로 제공한다. 정식 캠페인 선수 미션 완료를 위조하지 않고 필요한 자료·상태와 짧은 맥락 안내만 제공한다. 목표 시간은 25~40분이다.

예정 파일: `godot/data/missions/M05.json`, `M09.json`, 사이트/도구/안내 데이터, `godot/scenes/room.tscn`, 브라우저·도구 장면, ko/en 시험 문자열·폰트, 해결/오답/대안 fixture, 세 OS 초기 export preset.

완료 조건:

- 세 사건의 침투·조사·회수 목표와 후일담을 완주하고, 이전 명령/도구와 새 기능을 조합할 수 있다.
- 브라우저·터미널·도구가 같은 상태/권한 결과를 보며 두 터미널과 브라우저 세션은 섞이지 않는다.
- 열린 포트는 서비스 존재로만 처리한다. 탐색→서비스/인증/설정→가상 세션→목표 경로와 closed/filtered·접근 실패를 구분한다.
- 유효한 대안 풀이·안내/도구 스킵으로 캠페인이 진행한다. 새 기술을 쓰지 않은 완료는 간단한 기록에서 해당 기술 `not_assessed`로 남기고 상세 학습 분석은 요구하지 않는다.
- 가능한 사건에 의미 있는 대안 해법을 검증한다. 단순 순서 변경만 별도 해법으로 세지 않는다.
- 잘못된 요청·명령·권한·재시작·저장 복구·창 닫기가 진행을 막지 않는다.
- 작은 3D graybox에서 컴퓨터→2D OS→작업실 전환·입력 차단/복원·창 상태 유지가 된다.
- ko/en 문자열·CJK fallback·긴 문장 시험과 세 OS 초기 export smoke를 수행한다. 패키지 생성과 실제 실행 가능 여부를 구분하고 환경을 명시한다.
- 다중 사건/재방문을 도입하면 완료·회수 자료·명시적 선택 효과를 이월한다. 임의 원격 파일 전체를 다음 사건에 병합하지 않는다.

입문자 약 5명으로 막힘·반응·페이싱을 관찰하고 숙련자에게는 정해진 풀이를 알려주지 않는다. 각 플랫폼 전체 완주·완성 번역·최종 OST는 후속 단계다. 작은 표본으로 교육 효과를 통계적으로 입증했다고 말하지 않는다.

## P3. MVP 10미션

M01~M10, 캠페인 선택·도구 도움말·선택 복습·설정·ko/en을 연결한다. 목표 90~150분이다. 첫 사건과 후속 사건의 실제 제작·검수·번역·테스트 시간으로 남은 공수를 재산정한다.

세 OS에서 실제 플레이 완주·입력·설치/업데이트·저장 보존을 확인하고 오디오 3큐·텍스트 확장·폰트·언어 전환을 검증한다. 각 OS 검증은 확보한 환경과 경로를 명시하며 미확인 범위를 통과로 대신하지 않는다.
완료 조건은 10개 사건의 초기 미충족·유효 경로·대표 오답·지원 대안 재생, 목표/제약 유지, 사용자 주요 막힘 해결, ko/en 누락 0과 실제 플랫폼별 결과다. 빌드 생성만으로 재미·학습·플랫폼 완주를 판정하지 않는다.

### 필요가 생겼을 때만 추가하는 상세 계약

| 기능 | 도입 조건과 검증 | P1의 대체 |
|---|---|---|
| dependency_versions/claim_phase | P2/MVP 이후 여러 정책/세션/경로의 현재 주장이 독립적으로 변할 때, 관련 주장만 재검증 | 현재 WorldState 목표/제약 재평가+과거 관찰 보존 |
| pending_jobs | P2/MVP 이후 실제 비동기 효과·취소·재시작 수명 처리가 필요한 사건이 생길 때 | 동기 처리+결과 표시용 UI progress |
| content_hash 호환표/migration | MVP 이후 여러 콘텐츠/저장 버전의 업데이트 호환을 지원할 때 | save_version 일치·명시 오류·원본/tmp/bak 보존 |
| 상세 LearningState/분석 루브릭 | MVP 이후 선택 복습/힌트/재학습 이력을 사용자에게 제공할 때 | 학습을 통과에서 분리하고 미평가를 숙달로 추정하지 않음 |

고급 구조를 늦춰도 보장은 유지한다. 창 닫기는 보기만 닫고, 학습/캠페인 통과를 분리하며, 이월은 다중 미션부터 명시하고, 관찰은 연속 읽기로 서로 무효화하지 않는다. 기록 기능을 추가했다면 저장/재시작으로 기존 학습·선택을 지우지 않는다.

## P4. 1.0 메인24+선택4

네트워크 침투·웹·서버/시스템·계정·로그/패킷을 연결한 6장 메인24개와 선택4개를 완성한다. [PACING_AND_STORY.md](PACING_AND_STORY.md)의 480분+240분 예산으로 빠른 첫회 8시간/탐색 12시간의 깊이와 선택 탐색을 검증한다.

작은 3D 작업실의 최종 표현, 6개 언어 검수, OST 7큐를 각각 추적한다. 특정 도구·퀴즈·원인 설명을 강제하지 않고 실제 풀이 경로가 후일담에 반영되는지 확인한다.
R01 리버싱·P01 포너블은 MVP 이후 작은 모델 스파이크를 통과한 경우의 선택 사건 후보로 별도 산정한다. 모바일·AD·클라우드·무선/IoT는 별도 후속 세계 모델이다. [분야 판단](DOMAIN_SCOPE.md)

## P5. 출시·패키징·유지

Windows/macOS/Linux의 다운로드 파일·설치/실행·입력·저장·오디오·업데이트 증거를 모은다. 서명·배포 채널·가격·등급·권리 확인은 출시 준비에서 결정하며 스토어 등록을 별도 작업으로 본다.
산출물에는 버전·commit·SHA256, 지원 OS/CPU·언어, 알려진 문제, 세이브 호환성, 크레딧·자산 권리를 포함한다. 업데이트마다 해당 버전의 저장 보존과 기존 캠페인 회귀를 확인한다.

headless 테스트는 실제 IME·렌더·음향·드래그·설치/업데이트·사람의 재미 판단을 대체하지 않는다. 실제 창/산출물 검증을 단계별로 추가한다. 민감 경계의 정적 검사도 모든 런타임 우회를 증명하는 만능 검사는 아니다.

첫 제품 소스를 추가할 때 마련할 명령 계약은 다음과 같다. gate는 아래 두 실제 검사와 지원 경계 검사를 묶는다. export는 P2 이후 별도 빌드 작업이다.

```sh
./tools/gate.sh
godot --headless --path godot --script res://tools/validate_content.gd
godot --headless --path godot --script res://tests/headless/run_all.gd
```

runner는 실패 시 비영 종료를 반환한다. 단순 assert 로그·빈 fixture·누락 검사 skip으로 성공을 반환하지 않는다. 결과 기록에는 PASS/FAIL/NOT_RUN, 명령·환경·대상 commit·산출물·한계를 남긴다.

## 계획 공수와 중단 조건

1인+AI, 주당 20~30시간을 가정한 기존 전체 추정은 총 18~30주·약 360~900시간이다. P0/P1을 줄였다고 최종 3D·세 OS·번역·OST 제작량이 사라지지는 않는다. P1 한 사건과 P2의 후속 사건 실측 전에는 약속 날짜로 쓰지 않는다. R01/P01은 별도 산정한다.
P0 입력 결함이 지속되면 창 선택부터 수정한다. P1에서 자료 회수·의뢰인 반응이 재미없거나 진행이 막히면 사건 수를 늘리지 않는다. 대부분의 시간이 운영체제·편집기·고급 프레임워크 제작으로 새면 한 사건의 핵심 흐름으로 돌아간다.

## 현재 문서 개정의 검증

Markdown 상대 링크, JSON 예시 문법, P0/P1 최소 계약, 단계 수량·미션 ID·학습/캠페인 분리, 최신 이야기·경보 방향과 Git 변경 범위를 확인한다. 이 정적 검증을 게임 gate 통과나 실제 플레이 결과로 표기하지 않는다.
