# 외부 제안·예시 코드의 비판적 검토

입력: 사용자가 전달한 Gemini의 기법·게임화 제안과 JavaScript 예시. 목적은 유용한 원리를 추리고 오류를 설계 계약에 반영하는 것이다. **예시를 실행·검증한 코드로 취급하지 않으며 그대로 제품에 복사하지 않았다.** 설치형 Godot 방향은 유지한다.

## 1. 채택할 원리

- 내부 네트워크·호스트·파일·계정·세션·명령을 분리한다.
- 정찰에서 얻은 정보를 침투·권한·내부 이동에 재사용한다.
- 브라우저·터미널·요청 편집·패킷·로그 도구를 같은 세계에 연결한다.
- 긴 분석을 작은 시각 모델과 짧은 의사코드로 설명한다.
- VM·Docker 없이 초기 시제품을 만든다.
- 자동완성·히스토리·지원 문법 도움말로 반복 입력을 줄인다.

다만 ‘상태 트리와 파서만으로 실제 Linux와 네트워크를 완벽하게 모사’한다는 목표는 채택하지 않는다. 프로세스·권한·파일·소켓·라우팅·프로토콜·타이밍에는 별도의 의미 규칙이 필요하다. **정의한 부분집합을 일관되게 모사하는 것**이 목표다.

## 2. 기법·학습 설명의 교정

| 제안 | 판정 | 반영할 정확한 규칙 |
|---|---|---|
| 포트·서비스·버전 출력 | 채택 | open/closed/filtered, 경로·서비스 구분. 배너는 단서 |
| 오래된 버전이면 도구로 바로 침투 | 수정 | 패치·설정·인증·도달 가능성 등 사건의 취약 조건을 확인 |
| OSINT와 후보 사전 | 채택·제한 | 허구 자료를 연결하는 추론. 모든 사건을 생일 맞히기로 만들지 않음 |
| 알려진 SQLi 문자열이면 관리자 | 수정 | 입력이 제한된 질의 구조에 미치는 의미를 모델링. 매 입력에 같은 우회 보장 금지 |
| Metasploit식 실행 | 제한 채택 | 모듈 요구·대상 기능·설정·권한·연결 조건을 검사. 열린 포트에 만능 쉘 금지 |
| 버퍼·반환 정보 시각화 | 선택 검증 | 지정 가상 모델의 바이트·주소·보호 규칙을 보여주기 |
| 짧은 의사코드·분기 분석 | 선택 검증 | 원인과 입력의 관계를 해석. 자동 정답 공개로 축소하지 않기 |
| 패킷에서 비밀번호 찾기 | 수정 | 평문인 경우와 암호화된 경우를 구분. TLS를 그냥 읽을 수 있다고 가르치지 않기 |
| 해시 ‘해독’ | 수정 | 후보를 같은 설정·salt로 계산해 저장값과 비교 |
| SUID 설정 파일·스크립트면 root | 수정 | SUID 바이너리와 특권 프로세스가 실행하는 수정 가능 스크립트는 다른 조건 |
| 모든 미션의 흔적 삭제 | 제외 | 사건 목표에 따라 증거 보존·최소 변경이 더 중요할 수 있음 |
| 모든 침투에 60초 추적 | 제외 | 학습 모드와 현장 모드 분리. 경보·대응은 선택적인 긴장 규칙 |
| 피벗 깊이만큼 추적 지연 | 게임 규칙으로만 후보 | 실제 익명성·추적 방지 원리라고 가르치지 않기 |
| 포트 노킹으로 IDS 만능 우회 | 보류 | 넣어도 특정 가상 접근 정책 사건에 한정 |

기술 근거:

- 서비스 버전과 보안 패치: [Red Hat backport 정책](https://access.redhat.com/security/updates/backporting).
- 비밀번호 해시와 암호화의 차이: [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
- TLS 내용을 보기 위한 조건: [Wireshark TLS 문서](https://wiki.wireshark.org/TLS).
- Linux가 인터프리터 스크립트의 set-user-ID/set-group-ID 비트를 무시하는 점: [execve(2)](https://man7.org/linux/man-pages/man2/execve.2.html).
- 고정 메모리 주소의 일반화 한계: [Linux 주소 무작위화 설정](https://docs.kernel.org/admin-guide/sysctl/kernel.html#randomize-va-space).

## 3. JavaScript 예시의 정적 검토

아래는 전달된 코드의 정적 검토다. 전체 예시는 실행하지 않았다. Map 직렬화의 항목 손실과 `ls -la /etc` 옵션 파싱의 경로 손실 두 가지는 별도 최소 언어 자가 검사로 재현했다. 실제 구현에서는 같은 문제를 방지하는 작은 회귀 테스트로 전환한다.

| 위치·조건 | 문제와 영향 | 설계에서 고칠 것 |
|---|---|---|
| `cmdExploit` | 포트가 열려 있으면 취약점·계정·서비스 종류와 무관하게 guest 쉘을 줌 | ServiceDef의 명시적 취약 조건·권한·연결 방향 검사 |
| `cmdNmap`/네트워크 조회 | 전체 Map을 직접 조회. subnet·라우팅·방화벽이 실제 접근 판정에 사용되지 않음 | 발견·경로·세션 출발점·필터링을 별도 계산 |
| `parseInput`, `ls -la /etc` | 모든 옵션이 다음 토큰을 값으로 소비해 경로가 args에서 사라짐 | 명령별 옵션 스키마와 arity 사용 |
| 빈 따옴표·미완성 따옴표 | `||`로 토큰을 선택해 빈 문자열이 보존되지 않고 잘못된 인용을 명확히 거부하지 않음 | 빈 토큰·이스케이프·인용 오류 계약과 테스트 |
| 명령 레지스트리·children의 객체 조회 | own-key 검사 없이 상속 속성까지 조회할 여지 | 명시적 레지스트리/Dictionary와 키 존재 검사 |
| `hasPermission` | readRole 하나만 검사. 그룹·비트·경로의 검색 권한·쓰기·실행이 없음 | 지원할 최소 POSIX 권한 부분집합을 공통 함수로 정의 |
| `cmdRm` | 파일 소유자로 삭제 가능 여부 판정. 부모 디렉터리 권한·디렉터리 삭제 규칙이 빠짐 | 삭제는 부모 write/search 및 범위·재귀 규칙 검사 |
| `cmdGdb` | 읽기/실행 권한 없이 분석 가능하고 GDB가 의사코드를 자동 제공하는 것처럼 표현 | 접근 검사와 게임용 BinaryLens/디버거의 범위를 분리 |
| `cmdPwn` | 두 정답값 비교만으로 성공, 메모리 변화·취약 타입 검증이 없음 | 작은 입력/메모리 모델을 만들거나 ‘시연용 답 맞히기’라고 한정 |
| SUID·사용자 변경 | 파일 소유자·실행 조건과 무관하게 현재 세션 자체를 root로 변경 | 실제/유효 권한·프로세스 범위·복귀 규칙 분리 |
| 스택 표시 | 데이터의 주소·프레임·버퍼 설명이 고정 가정에 의존하고 서로 혼동될 수 있음 | 하나의 가상 ABI 계약에서 그림·계산·힌트를 생성 |
| `sessionStack` 하나 | 여러 터미널·역방향 접속·독립 연결의 관계를 충분히 표현 못 함 | 터미널별 세션과 연결 경로 ID 사용 |
| `JSON.stringify(network)` | JavaScript Map의 항목은 기본 JSON 직렬화에 포함되지 않음 | 명시적 snapshot DTO·ID 참조·버전·복원 검증 |
| 네트워크만 저장 | 사용자 세션·발견·미션·힌트·언어·창 상태 누락 | 저장 범위와 재구성 가능한 데이터를 구분 |
| 실시간 타이머 제안 | 재현·일시정지·불러오기·프레임/플랫폼 차이 미정 | 논리 시간·명시적 대기·경보 정책, 저장/복구 계약 |

JavaScript Map JSON 동작의 언어 근거는 [MDN Map](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Map)을 참고한다. 이 구현을 TypeScript로 옮겨도 도메인 규칙 누락이 자동 해결되는 것은 아니다.

## 4. Godot 설계에 반영한 계약

1. `WorldState`는 화면별 복사본이 아니라 공통 사실의 원본이다.
2. `CommandSpec`은 옵션별 인자 수·자료형·지원 범위를 가진다.
3. 네트워크 그래프는 연결됨·발견됨·접근 가능·로그인됨을 구분한다.
4. 가상 HTTP·SSH·FTP·DB의 서비스 규칙이 접근과 결과를 결정한다.
5. 파일 읽기·쓰기·실행·삭제는 같은 경로·권한 모듈을 사용한다.
6. 실패한 행동은 일부만 적용하지 않는다. 먼저 검증하고 상태를 바꾼다.
7. 저장은 명시적 ID 기반 snapshot으로 버전·검증·백업을 포함한다.
8. 목표는 특정 도구나 명령 문자열보다 결과·제약·유효한 근거로 판정한다.
9. 교육용 가상 분석과 실제 Linux/보안 원리의 차이를 설명한다.
10. 새로운 기법이 실제 상태 모델 없이 ‘정답 문자열 검사’만 추가되는 것을 막는다.

구체적인 코어·명령·데이터는 [ARCHITECTURE.md](ARCHITECTURE.md), 분야별 투자 우선순위는 [DOMAIN_SCOPE.md](DOMAIN_SCOPE.md)를 따른다.

## 5. 보류하는 확장

React/Node로 본편을 다시 만들기, 네트워크 상태를 DB에 넣었다는 이유만으로 멀티플레이가 완성된다고 보는 것, 실제 gdb/취약 바이너리 실행, 무제한 브루트포스·자동 공격, 대규모 MMO는 현재 범위가 아니다.

제안에서 가장 좋은 부분은 작은 상태 모델로 즉각적인 피드백을 만드는 것이다. 가장 위험한 부분은 그 모델을 ‘완벽한 실제 OS’ 또는 ‘실전 기법 전체’로 설명하는 것이다. 이번 설계는 일관된 부분집합과 명시적 추상화를 택한다.
