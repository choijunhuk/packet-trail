# 분야 선택·침투 흐름·다중 해법의 권고

사용자가 언급한 분야를 모두 같은 깊이로 넣는 안은 권하지 않는다. **네트워크 침투와 사건 조사를 뼈대로 삼고, 웹·서버·Linux·계정·포렌식 모델을 재사용하는 캠페인**을 우선한다. 기초 리버싱과 포너블은 작은 독립 검증 뒤 선택 사건으로 채택한다.

## 1. 분류부터 구분한다

| 축 | 뜻 | 예 |
|---|---|---|
| 전술적 목표 | 지금 무엇을 이루려는가 | 정보 수집, 초기 접근, 발견, 권한 상승, 내부 이동, 수집 |
| 대상·환경 | 어디에서 일어나는가 | 웹 앱, 서버, 모바일, 기업 도메인, 클라우드, 무선망, IoT |
| 기법·분석군 | 어떤 원리로 접근하는가 | 웹 취약점, 자격 증명 분석, 리버싱, 바이너리 익스플로잇, 포렌식, 암호 분석 |

[MITRE ATT&CK](https://attack.mitre.org/tactics/enterprise/)의 전술은 기법의 목적을 뜻한다. 모든 사건이 같은 순서로 진행하는 절차가 아니다. ‘정찰→침투→권한 상승→흔적 삭제’를 모든 미션의 통과 순서로 고정하지 않는다.

[picoCTF](https://picoctf.org/resources.html)는 웹·리버싱·바이너리 익스플로잇·포렌식·암호 등의 학습 자료를 구분한다. 이는 분야를 구분하는 참고이지 우리 게임의 공식 커리큘럼 인증이 아니다.

## 2. 권장 범위와 이유

| 분야 | 권고 | 구현·게임상의 이유 |
|---|---|---|
| 정찰·OSINT | 핵심 | 사이트·메일·파일·인물 관계를 조사하는 스토리와 직결 |
| 네트워크·서비스·포트 | 핵심 | 대상 발견과 도달 가능성이 모든 경로의 공통 뼈대 |
| 웹 취약점·인증·인가 | 핵심 | 브라우저·요청 도구·서버가 같은 모델을 재사용 |
| Linux 파일·권한·취약 설정 | 핵심 | 서버 접근 이후의 판단과 권한 차이를 표현 |
| 피보팅·내부 이동 | 핵심 종합 사건 | 외부·중간 서버·내부 자원의 연결을 이해하게 함 |
| 자격 증명 감사 | 제한된 핵심 | 허구 후보·salt·검증값 비교, 잠금·속도 제한의 의미 |
| 로그·패킷·파일 포렌식 | 핵심 | 사건의 진실을 밝히고 이전 조치의 효과를 검증 |
| 기초 리버싱 | 선택 사건 후보 R01 | 소형 허구 프로그램의 문자열·분기·설정 분석부터 가능 |
| 기초 포너블 | 검증 후 선택 사건 후보 P01 | 입력→메모리 변화→제어 흐름을 보여주는 별도 작은 모델 필요 |
| 암호 개념 | 보조 사건 | 인코딩·해시·암호화의 차이. 암호 알고리즘 제작 게임까지 확장하지 않음 |
| 모바일 | 후속 캠페인 | 저장소·앱 권한·Android/iOS·플랫폼 상호작용이 추가됨 |
| AD·클라우드 IAM | 후속 | 조직 신뢰·역할·정책의 새 모델 필요 |
| Wi-Fi·IoT·펌웨어 | 후속 | 무선·기기·펌웨어 모델이 기존 HTTP 사건과 크게 다름 |

비용·재사용성 평가는 이 프로젝트에 대한 설계 판단이며 공식 생산성 수치가 아니다. 모바일을 휴대전화 모양의 웹 폼으로, AD를 root 계정 퍼즐로 바꿔 이름만 붙이는 것은 피한다. [OWASP MASVS](https://mas.owasp.org/MASVS/), [MASTG](https://mas.owasp.org/MASTG/)

## 3. 네트워크 침투 사건의 예

```text
허구 조직 사이트·메일·기록
        ↓ 여러 단서로 대상 발견
외부 웹/SSH/자료 서비스 ── 서비스별 조건·계정·정책 조사
        ↓ 유효한 진입 경로 선택
제한된 가상 세션 ── 파일·권한·내부 경로·통신 기록 발견
        ↓ 필요할 경우 권한 상승/피벗
내부 대상 ── 목표 자료·사건 사실 확인
        ↓ 사건별 제약을 지키며 보고·조치·재검증
후일담·새 조사 가능성
```

포트 스캔은 문을 부수는 기술이 아니라 서비스와 상태를 관찰하는 활동이다. 같은 포트라도 서비스·설정·인증·경로·패치 상태가 다르면 결과가 달라진다. `open/closed/filtered`를 구분하고 버전 배너만으로 취약점을 확정하지 않는다. [Nmap 공식 매뉴얼](https://nmap.org/book/man.html), [Red Hat backport 설명](https://access.redhat.com/security/updates/backporting)

권한 상승이나 내부 이동이 필요 없는 사건도 있다. 웹 계정의 정상 기능으로 이미 목표를 충족하면 불필요한 root 획득을 강제하지 않는다. 로그 보존·서비스 유지가 목적이면 무작정 삭제·종료하는 경로는 제약 위반이다.

## 4. 숙련자를 위한 다중 해법

사건의 판정은 세 가지를 확인한다.

1. 요구한 사건 결과가 달성되었는가?
2. 보호 대상·정상 기능·데이터 보존 등 제약을 지켰는가?
3. 제출한 결론을 뒷받침하는 유효한 관찰이 있는가?

도구 사용 횟수·특정 명령·튜토리얼 체크·증거 핀은 통과 조건이 아니다. `any_valid_evidence`는 아무 주장이나 받아준다는 뜻이 아니라 동일 사실을 입증하는 서로 다른 관찰을 허용한다는 뜻이다.

예를 들어 웹 요청 비교로 자료 소유권 문제를 증명해도 되고, 허용된 별도 서비스의 감사 기록으로 같은 사실을 증명해도 된다. 해법은 단순히 같은 명령의 순서만 바꾼 것이 아니라 다른 정보·접근 경로를 써야 한다.

반대로 새로운 백도어를 심거나 모든 서비스를 꺼서 제약을 깨뜨리는 것은 대안 정답이 아니다. 사건에 존재하지 않는 취약점이나 아직 구현하지 않은 모든 실제 Linux 동작을 지원한다고 약속하지 않는다.

**캠페인 완료와 학습 평가는 분리한다.** 새로 소개한 기술을 쓰지 않고 사건을 해결해도 진행한다. 그 기술은 `not_assessed`로 남기고 선택 연습을 제공한다. 이미 아는 도구를 튜토리얼 완료 전까지 잠그지 않는다.

## 5. 리버싱과 포너블을 넣는 최소 기준

R01은 15줄 내외의 허구 의사코드·문자열·호출 관계를 비교해 설정이나 검사 분기의 의미를 알아내는 선택 사건으로 검증한다. 도구가 비밀 값을 곧바로 정답으로 표시하는 퍼즐은 피한다. 실제 GDB가 자동 디컴파일러라는 식으로 설명하지 않는다.

P01은 작은 가상 실행 모델에서 입력 바이트가 버퍼·인접 값·제어 정보에 미치는 결과를 보여준다. 주소·프레임·정수 크기·엔디언·보호 규칙은 해당 가상 모델의 계약으로 명시한다. 입력과 상태 전이로 결과를 계산하며, 정답 offset과 주소를 문자열 비교하는 것만으로 ‘포너블 엔진’이라고 부르지 않는다.

선택 사건도 터미널·파일·증거·스토리와 연결되어야 한다. 새로운 분석 화면만 띄우고 정답을 맞히면 끝나는 별도 퀴즈 모음은 권하지 않는다. 실제 네이티브 바이너리 실행·범용 CPU 에뮬레이터·수만 줄 어셈블리는 범위 밖이다.

채택 게이트: MVP의 기본 루프가 안정된 뒤, 각 모듈의 작은 시제품에서 ‘결과를 이해하는가·기존 도구와 연결되는가·추가 제작량을 감당할 수 있는가’를 검증한다. 통과하면 24개 메인 외 선택 사건으로 추가하고 공수를 다시 산정한다. 미통과면 후속 확장으로 남긴다. 현재 R01/P01은 구현 또는 확정 출시 약속이 아니다.

## 6. 지루함을 막는 기준

새 개념 하나+익숙한 기술 1~2개, 짧은 사건 뒤 다른 원리의 사건, 장 마지막의 자유 조합을 기본으로 한다. 숙련자는 안내를 건너뛰고, 초보자는 안전하게 반복한다. 도구 설치·긴 대기·똑같은 로그 정리를 매번 반복시키지 않는다.

다양성은 아이콘 수보다 ‘같은 도구로 다른 질문에 답하는가’와 ‘새로운 유효한 해결 경로가 있는가’로 판단한다. 24개 메인은 기반 모델을 공유하도록 설계하고 모바일·리버싱·무선망을 모두 별도 본편으로 동시 제작하지 않는다.
