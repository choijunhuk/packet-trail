# Packet Trail · 학습 과정과 24미션 설계

문서 상태: 구현 전 교육·콘텐츠 계획. 2026-11-04 기준. 게임 코드·플레이테스트·학습 효과 검증은 아직 없다.
사용자 확정 방향은 설치형 게임, 게임 내 가상 OS·여러 터미널·가상 브라우저·해킹 도구·리눅스식 명령·스토리, 앞서 배운 기술을 재사용하는 학습이다.
추천 형태는 작은 3D 작업실에서 컴퓨터를 사용하면 가독성 좋은 2D 가상 OS가 열리는 방식이다. Godot 4+GDScript, 도시 ‘해람’, 장 제목·사건·인물·미션 수·평가 기준은 설계 제안이다. 사용자 확정 시간 목표는 빠른 첫회 약 8시간·탐색 약 12시간이며 아래 예산은 미실측 설계다. 실제 Hacknet 엔진이나 전체 도구 동작 호환을 재현하지 않는다.
플레이어 입력은 내부 시뮬레이터에서만 처리한다. 실제 호스트 셸·실제 서버·외부 네트워크 요청·실제 JavaScript 실행은 학습 기능에 포함하지 않는다.

## 1. 배운다는 것의 정의

목표는 명령 문자열을 외워 맞히는 일이 아니라, 보이지 않던 경로와 권한을 알아내고 허구 시스템에 접근해 필요한 사실을 입증하는 일이다. 네트워크 침투 사건을 중심으로 조사·잠입·복구가 교차하며, 매 사건을 보안 설정 수정으로 끝내지 않는다.
권장 흐름은 **의뢰 → 관찰 → 가설 → 비교 실험 → 필요한 접근·조치 → 제약·결과 검증 → 회고**다. 구체적인 순서·도구·증거보드 사용은 강제하지 않는다.
메일은 의뢰와 이해관계, 브라우저는 실제 서비스의 반응, 터미널·도구는 숨은 구조, 증거보드는 추론을 맡는다. 도구를 얻었다는 사실만으로 이야기를 진행시키지 않는다.
기술 학습 경로는 처음 소개→가이드 사용→독립 선택→이전 기술과 조합으로 설계한다. 튜토리얼은 건너뛸 수 있고, 이 단계를 밟았는지는 캠페인 통과 조건으로 쓰지 않는다. 새 도구의 첫 소개와 독립 사용도 같은 학습 관측값으로 기록하지 않는다.
도움말·자동완성·명령 이력은 계속 허용한다. 구문 지원을 사용해도 개념 이해 평가를 낮추지 않는다. 그래픽 도구와 동등한 가상 명령은 같은 상태 변화를 만든다.
캠페인 판정은 **목표 시스템 상태+정상 기능+대상/행동 제약+입증 가능한 증거(`any_valid_evidence`)**다. 특정 기술·도구 사용·교육 단계·증거보드 핀·원인 설명 퀴즈를 통과 조건으로 삼지 않는다.
완료 증거는 `대상·관찰자 역할·요청 맥락·세계 상태 버전·결과`를 포함한다. 현재 목표 상태를 입증해야 하며, 복구 사건에서는 조치 전 캡처를 조치 후 증거로 제출할 수 없다.
자동 요청 기록·상태 감사·가상 로그·대조 실험 등 유효한 증거를 모두 허용한다. 증거보드는 추론을 돕는 선택 도구이며 수동 고정 없이도 관찰 기록으로 입증할 수 있다.
아래 카드의 기술별 비교·원인 설명은 **권장 학습 경로와 학습 평가 조건**이다. 다른 지원 경로로 사건을 해결하면 스토리는 통과시키고, 사용하지 않은 기술은 ‘미평가’로 남겨 선택 연습을 제공한다.
**침투 목표**는 지정된 허구 세션·권한·표식/기밀 자료의 최소 확보, **조사 목표**는 사실·출처·접근 경로의 입증, **잠입 목표**는 불필요한 상태 변경 없이 접근하는 것이다. 실제 세계 공격·로그 삭제·무차별 자료 수집은 요구하지 않는다.
**복구 목표**는 일부 사건의 정책·기능 수리와 조치 후 허용/차단 쌍 검증이다. M01·M06·M07·M08·M12·M23은 복구를 필수로 하고, 다른 사건의 완화·패치는 캠페인 뒤 선택 연습으로 분리한다.
모든 유형에 대상/행동 제약과 정상 기능 보존 검사는 있지만, 침투 사건에서 발견한 결함을 반드시 고쳐야 통과하는 것은 아니다. 확보한 사실·최소 자료·조치 선택은 후속 대화와 엔딩에 반영한다.

## 2. 범위·선수 지식·안내 감소

| 단계 | 포함 | 추정 플레이 시간 | 학습 검증 목적 |
|---|---|---|---|
| 수직 시제품 | M01·M05·M09, 선수 학습 프리셋 | 25~40분 | 복구·침투 검증·기록 조사가 각각 놀이로 작동하는가 |
| MVP | M01~M10 | 90~150분 | 첫 기술을 다른 사건에서 스스로 재사용하는가 |
| 1.0 | 6장·메인 24개+선택 사건 4개 | 빠른 첫 플레이 약 8시간·탐색 포함 약 12시간 | 웹·네트워크·시스템 증거를 종합하는가 |

목표 시간의 실현 예산은 가설이다. 짧은 사건 8개×10분+일반 10개×19분+장말 6개×20분=조작 390분, 메인 대화·프롤로그/엔딩·OS 적응 90분으로 480분을 배정한다. 선택 사건·기록·대안 탐색·복습 등에 240분을 더해 12시간을 설계하며 [분량 예산](PACING_AND_STORY.md)과 중복 합산하지 않는다. 강제 대기·반복으로 시간을 채우지 않는다.
1.0 메인은 아래 24미션의 웹·서버/시스템·로그/패킷에 집중한다. 모바일·AD·클라우드·무선/IoT는 후속 범위다. 기초 리버싱 R01·포너블 P01은 작은 모델 검증을 통과한 경우의 선택 사건 후보이며 필수 미션이 아니다. 선택 사건 S01~S04와 분량 예산은 [PACING_AND_STORY.md](PACING_AND_STORY.md)를 따른다.
페이싱 원칙은 미션당 새 핵심 개념 1개와 앞서 배운 핵심 기술 1~2개 재사용이다. 카드의 여러 비교·조치는 그 개념을 확인하는 행동이며 새 이론 강의로 늘리지 않는다.
초기 대상은 터미널 경험이 없어도 읽기·키보드·마우스 조작이 가능한 한국어 입문자다. 최종 연령·대상군은 후속 결정이며 전문 교육·자격증·실전 숙련을 보증하지 않는다.
정식 캠페인은 이야기 순서대로 열되 아래 선수 ID는 권장 학습 경로의 개념 의존성이다. 별도 기술 시험·튜토리얼 시청·이전 도구 사용을 잠금 조건으로 추가하지 않는다.
시제품 M05는 M01~M04의 파일·서비스·HTTP 개념을 90초 이내 예시에서 제공하고, M09는 이에 인증·인가 차이를 더한 프리셋을 쓴다. 이 예시를 본 기록은 정식 미션 완료와 분리한다.
안내 강도는 첫 소개의 ‘관찰 위치+다음 행동 예시’, 가이드 사용의 ‘비교할 두 상태’, 독립 사용의 ‘문제와 이용 가능한 도구’, 조합의 ‘의뢰와 범위’로 줄인다.
안내 감소는 미션 번호만으로 강제하지 않는다. 선행 개념의 독립 증거가 없으면 선택 복습을 제안하고, 실패했다고 이미 연 도구를 잠그지 않는다. 숙련자는 처음부터 안내를 끌 수 있다.

| 도구군 | 첫 소개·가이드 사용 | 독립·재사용 | 후반 조합 |
|---|---|---|---|
| 가상 Browser | M01 주소·링크·화면 상태, M04 요청 연결 | M05·M08·M10·M12 | M21·M24 |
| FileLens | M02 경로·파일·검색, 같은 사건의 두 번째 로그 | M11·M16·M18 | M23·M24 |

## 3. 6장·24미션 카드

### 1장 · 끊어진 안내판: 관찰과 요청의 기초

#### M01 · 돌아오지 않는 도착 안내
- **선수 ID:** 없음. **유형:** 복구·입문. **스토리:** 복구팀 신입인 플레이어에게 정비사 ‘도윤’이 정류장 안내가 멈췄다는 첫 가상 메일을 보낸다.
- **첫 학습:** 의뢰 범위·가상 대상·앱 전환·보이는 화면과 실제 서비스 상태의 구분. **재사용 기술:** 없음; 이후 사건의 기본 조사 루프를 만든다.
- **도구:** 메일, 가상 Browser, 터미널 도움말, 서비스 연결 카드. 주소·대상 선택은 게임 세계 목록 안에서만 이루어진다.
- **플레이 행동:** 의뢰의 허용 대상 확인 → 안내 사이트와 상태 페이지 비교 → 폐기된 안내 별칭을 찾아 담당 연결을 현행 서비스로 교체한다.
- **상태 기반 성공:** 범위 안 대상 발견, 낡은 연결과 정상 서비스의 비교 증거, 올바른 별칭 연결, 일반 승객 화면의 새 도착 정보 표시가 모두 성립한다.
- **오답 복구:** 빈 주소·잘못된 별칭에는 대상 없음/연결 불일치를 구별해 표시한다. 연결 카드 이전 값과 되돌리기를 제공하고 서비스가 복구됐다는 거짓 성공을 주지 않는다.
- **전이 질문:** “같은 화면 오류가 나도 원인이 다른 두 경우를 어떻게 구분할까?” 다른 이름의 안내판을 링크·상태 증거로 확인하게 한다.

#### M02 · 기록이 가리킨 뒷문
- **선수 ID:** M01. **유형:** 사건 조사. **스토리:** 안내는 돌아왔지만 야간 동기화만 끊긴다. 도윤은 파일 이름을 모르는 상태로 기록 조사를 요청한다.
- **첫 학습:** 현재 경로·상대/절대 경로·목록·파일 읽기·조건 검색·시간 순서. **재사용 기술:** 의뢰 범위와 화면/상태 구분.
- **도구:** FileLens, LogLens, 리눅스식 `pwd`·`ls`·`cd`·`cat`·`grep`의 한정된 가상 동작과 도움말.
- **플레이 행동:** 가상 작업 폴더 탐색 → 여러 로그에서 동일 사건 식별자 찾기 → 옛 동기화 대상과 최신 설정 비교 → 누가 목적지를 바꿨는지 최소 기록을 확보한다. 연결 수정은 선택 후속 연습이다.
- **상태 기반 성공:** 실패 시간대·변경 주체·대상 경로를 연결한 유효 증거와 지정된 변경 기록이 확보되고 원본 로그·안내 서비스는 보존된다. 파일명이나 특정 검색 명령은 강제하지 않는다.
- **오답 복구:** 디렉터리와 파일, 접근 거부와 없는 경로를 구분한다. 검색 결과 0건이면 검색 범위·대소문자·시간 필터를 표시한다.
- **전이 질문:** “파일 이름이 바뀌면 어떤 단서를 유지할까?” 새 이름의 로그에서 사건 식별자로 같은 원인을 찾는다.

#### M03 · 살아 있는 포트
- **선수 ID:** M01·M02. **유형:** 침투·첫 접근. **스토리:** 유지보수 담당자는 꺼진 서버라고 설명하지만 낯선 가상 서비스가 살아 있다. 외부 제보자가 첫 진입 경로를 찾으라고 요청한다.
- **첫 학습:** 호스트의 포트는 서비스의 문이며 열림 자체가 취약점은 아니라는 구분. `open`·`closed`·`filtered`는 해당 관찰 지점의 결과이며 필터링 원인을 단정하지 않는다([Nmap 포트 상태 설명](https://nmap.org/book/man-port-scanning-basics.html)). **재사용 기술:** 파일의 대상 단서, 로그 시간 비교.
- **도구:** NetProbe, FileLens, 두 개의 가상 터미널 세션. 발견 범위는 의뢰가 허용한 소규모 내부 토폴로지다.
- **플레이 행동:** 설정에서 대상 후보 획득 → 열린/닫힌/필터링 포트 비교 → 관찰 지점별 경로 확인 → 제공된 가상 인증 단서와 서비스 설정을 조합해 제한 세션에 접속한다.

- **전이 질문:** “DB에 안전하게 저장되면 화면에서도 안전한가?” 저장과 표시의 서로 다른 경계를 증거에 연결한다.

- **플레이 행동:** 정상 첨부의 기준 경로 확인 → 가상 경로 해석 비교 → 허용 세계의 경계 밖 목표 표식 파일 접근 또는 동등한 감사 증거 확보 → 정상 첨부 다운로드 보존 확인.
- **상태 기반 성공:** 게임 안의 지정된 표식 파일과 그 접근 경계가 입증되고 다른 자료·파일 내용·정상 다운로드는 보존된다. 호스트 경로는 존재하지 않는다. 경로 검사 수정은 선택 후속 연습이다.
- **오답 복구:** 없는 파일·정책 거부·범위 밖 목표를 구분한다. 파일 전체 잠금으로 목표를 놓치면 변경을 되돌릴 수 있다. 표식 이상의 자료를 얻을 이유가 없음을 목표 패널에 표시한다.
- **전이 질문:** “처음 글자가 자료실 경로와 같으면 안전한가?” 이름이 비슷한 이웃 디렉터리로 경계 검증을 수행한다.

#### M12 · 사진이라는 이름의 파일
- **선수 ID:** M04·M10·M11. **유형:** 복구. **스토리:** 정비 사진 업로드 이후 자료 서버에 이상한 가상 처리 작업이 등록된다.
- **첫 학습:** 확장자·형식·저장 위치·실행 권한의 분리, 업로드 처리 경계. **재사용 기술:** 경로 허용 범위·출력 처리·정상 기능 대조.
- **도구:** Browser, FileLens, RequestLab, 업로드 처리 추적 카드. 업로드는 제공된 허구 파일 레코드 선택이다.
- **플레이 행동:** 파일 이름·내용 형식·처리 경로 대조 → 업로드 허용 규칙·비실행 저장 위치 적용 → 잘못된 형식과 정상 사진 재검증.
- **상태 기반 성공:** 형식 불일치가 거부되고 업로드 파일이 실행 경로에 놓이지 않으며 정상 사진 등록·열람은 된다. 확장자 검사만으로 완료되지 않는다.
- **오답 복구:** 사진 전체 금지는 정상 업무 실패로 돌려준다. 허용 형식과 제공된 모형의 지원 범위는 도움말에서 명시한다.
- **전이 질문:** “이름이 안전해 보여도 처리 경로가 위험할 수 있을까?” 새 확장자의 허구 파일에서 같은 경계를 찾는다.

### 4장 · 연결된 경계: 실행·내부망·시스템 권한

#### M13 · 진단 버튼의 두 번째 일
- **선수 ID:** M02·M09·M12. **유형:** 침투·가상 실행 검증. **스토리:** 진단 버튼 뒤의 가상 작업 실행 경계가 의심된다. 정비 시스템을 손상하지 않는 허구 검증 작업으로 진입 가능성을 확인한다.
- **첫 학습:** 명령 삽입의 데이터/명령 경계, 셸 조합을 피하는 고정 작업·인자 분리. **재사용 기술:** 입력 경계와 처리 추적, 가상 파일·권한 읽기.
- **도구:** RequestLab, FileLens, LogLens, 가상 작업 추적. 등록된 모형 명령만 해석하고 실제 프로세스·셸 호출은 없다.
- **플레이 행동:** 정상 진단의 모형 작업 목록 확인 → 입력이 명령 구조에 들어가는 경로 조사 → 등록된 무해 가상 검증 작업 실행 또는 동등한 작업 감사 → 현재 작업 계정·정상 진단 상태 확인.
- **상태 기반 성공:** 지정된 허구 검증 작업의 실행·계정 범위가 입증되고 파괴적 작업·범위 밖 파일 변경·진단 중단이 없다. 인자 분리와 고정 작업 전환은 선택 후속 연습이다.
- **오답 복구:** 지원되지 않는 입력은 실제 셸로 넘기지 않고 모형 범위 오류로 반환한다. 실행되지 않은 명령 문자열은 성공 증거가 아니다. 잘못된 가상 작업은 해당 체크포인트에서 재시도한다.
- **전이 질문:** “SQLi와 원인이 닮았어도 고쳐야 하는 경계가 왜 다른가?” 쿼리 해석기와 가상 작업 해석기를 구분한다.

#### M14 · 서버만 볼 수 있는 주소
- **선수 ID:** M03·M04·M13. **유형:** 침투·내부 피벗. **스토리:** 시민 브라우저에서는 닿지 않는 기록이 미리보기 서버 뒤에 있다. 허용된 내부 피벗으로 표식 서비스의 사실을 확인한다.
- **첫 학습:** SSRF·서버 관찰 지점·목적지 제약, 클라이언트와 서버의 접근 가능 범위 차이. **재사용 기술:** HTTP·서비스 발견·입력 흐름.
- **도구:** RequestLab, TraceRoute, NetProbe, LogLens. 모든 주소와 내부망은 가상 노드 그래프다.
- **플레이 행동:** 브라우저/서버 관찰 지점 비교 → 미리보기 요청의 가상 최종 목적지 추적 → 서버를 경유해 지정 내부 표식 서비스에 접근 → 서버 주체·도달 범위·응답 근거 확보.
- **상태 기반 성공:** 지정 내부 표식의 응답과 요청 주체·경로가 입증되고 다른 관리 자료·시민 미리보기는 보존된다. 내부 도달을 관리자 권한으로 간주하지 않는다. 목적지 제한 조치는 선택 후속 연습이다.
- **오답 복구:** 최초 주소·최종 목적지·인증 거부를 따로 표시한다. 미리보기 전체 차단으로 조사 경로를 닫으면 되돌릴 수 있다. 범위 밖 내부 노드는 접근하지 않는다.
- **전이 질문:** “내 PC에서 열리지 않는 주소에 서버도 못 갈까?” 새 노드에서 요청 주체와 경로를 선택한다.

#### M15 · 닫혔다고 생각한 관리망
- **선수 ID:** M03·M14. **유형:** 잠입·관리 세션. **스토리:** 관리망은 외부에서 보이지 않는다는 주장과 관찰 결과가 충돌한다. 시민 서비스를 건드리지 않는 조용한 진입 경로를 찾아야 한다.
- **첫 학습:** 네트워크 경로·노출 서비스·분리 정책, 도달 가능성과 로그인 권한의 차이. **재사용 기술:** NetProbe·TraceRoute·관찰 지점 비교.
- **도구:** 두 가상 터미널, NetProbe, TraceRoute, 연결 정책 카드.
- **플레이 행동:** 두 노드의 open/closed/filtered와 방화벽 경로 비교 → 잘못 열린 중계·서비스 설정 조사 → 제공된 허구 인증 결함 또는 허용된 대안 경로로 읽기 제한 관리 세션 접근 → 정상 서비스 확인.
- **상태 기반 성공:** 지정 관리 세션의 읽기 접근·출발 지점·현재 권한이 입증되고 서비스 중단·범위 밖 변경이 없다. 잠입의 제약은 불필요한 상태 변경 금지이며 로그 삭제를 요구하지 않는다. 방화벽 교정은 선택이다.
- **오답 복구:** 열린 포트·로그인 성공·목표 권한을 구분한다. 서버를 끄거나 모든 망을 열면 제약 실패로 알려준다. 관찰 지점을 바꾸면 결과가 달라질 수 있음을 표시한다.
- **전이 질문:** “관리 포트에 비밀번호가 있으니 외부 노출도 괜찮을까?” 도달 제한과 인증을 별개 통제로 설명한다.

#### M16 · 모두에게 열린 정비 폴더
- **선수 ID:** M02·M05·M13·M15. **유형:** 침투·접근 확장. **스토리:** 읽기 제한 정비 세션 뒤에 잘못된 그룹 권한이 남아 있다. 장말 사건의 누락된 기록을 얻기 위해 접근 범위를 넓힌다.
- **첫 학습:** Linux식 소유자·그룹·권한·최소 권한, 읽기·쓰기·실행과 디렉터리 접근. **재사용 기술:** FileLens·객체 인가·업무 역할 비교.
- **도구:** FileLens, AccessView, 가상 권한 명령 도움말, LogLens. 호스트 권한은 바꾸지 않는다.
- **플레이 행동:** 현재 계정·그룹과 파일 경로 확인 → 과도한 디렉터리/그룹 권한의 경계 조사 → 지정 모형 경로로 추가 읽기 권한 획득 또는 동등한 감사 경로 이용 → 목표 기록 최소 확보.
- **상태 기반 성공:** 초기 권한과 확장된 접근 범위·목표 기록이 입증되고 다른 사용자·파일·정비 업무는 보존된다. 루트 획득이나 권한 전체 개방은 목표가 아니다. 최소 권한 조정은 선택 후속 연습이다.
- **오답 복구:** 상위 폴더의 거부 지점을 단계별로 보여준다. 존재하지 않는 실제 Linux 권한 확장을 추측하게 하지 않으며 지원 모형의 그룹/작업 경로를 도움말로 확인할 수 있다.
- **전이 질문:** “파일 권한만 바꾸면 경로 전체를 통제한 것일까?” 상위 폴더 조건이 다른 변형을 확인한다.

### 5장 · 남겨진 기록: 자격 증명·가시성·사고 대응

#### M17 · 짧은 비밀의 긴 흔적
- **선수 ID:** M06·M16. **유형:** 감사·접근. **스토리:** 승인된 허구 계정 감사 자료에 기록 보관 서비스의 단서가 있다. 작은 오프라인 모형을 분석해 허용된 보관함에 접근한다.
- **첫 학습:** 오프라인 추측과 온라인 로그인 제한의 차이, 작은 사전·소금값·비용 모형의 역할. **재사용 기술:** 인증 정책·최소 권한·증거 범위.
- **도구:** CredAudit, FileLens, 감사 정책 카드. 소량의 창작 계정·창작 사전·해시 모형만 쓰며 실제 해시·사전 파일을 가져오지 않는다.
- **플레이 행동:** 가상 감사 자료·작은 사전 선택 → 후보 결과와 비용 모형 비교 → 해당 허구 계정으로 승인된 보관함의 제한 세션 확인 → 필요한 자료 최소 확보. 비밀 교체는 선택 후속 연습이다.
- **상태 기반 성공:** 지정 보관함 접근과 목표 허구 자료가 입증되고 다른 계정의 반복 로그인·범위 밖 감사가 없다. 다른 유효 접근 경로도 허용하며 사전 미발견을 강한 비밀번호의 증명으로 쓰지 않는다.
- **오답 복구:** 온라인 제한을 바꿔 오프라인 자료가 안전해졌다고 판단하면 경계 차이를 보여준다. 추정 비용을 실제 장비의 균열 시간으로 표시하지 않는다.
- **전이 질문:** “작은 사전에서 안 나왔다는 사실은 무엇까지 말해 줄까?” 미검출·불가능·안전의 차이를 선택한다.

#### M18 · 지워도 남은 설정
- **선수 ID:** M02·M07·M16·M17. **유형:** 사건 조사·자격 정보 접근. **스토리:** 지워진 가상 설정의 토큰 조각과 서비스 주소가 오래된 변경 이력에 흩어져 있다. 이를 재구성해 사건 기록의 출처를 확인한다.
- **첫 학습:** 저장소·설정 비밀 노출, 현재 파일 삭제와 비밀 폐기/교체의 차이. **재사용 기술:** 파일 검색·세션 무효화·권한 범위·이전 값 재검증.
- **도구:** FileLens의 가상 변경 이력, LogLens, AccessView, 자격 증명 관리 카드.
- **플레이 행동:** 현재 설정·이전 버전 비교 → 토큰 참조와 서비스 경로 재구성 → 승인된 허구 토큰의 효력·권한 확인 → 지정 기록을 읽기 접근한다. 토큰 폐기·대체는 선택 후속 연습이다.
- **상태 기반 성공:** 설정/토큰의 출처·현재 효력·목표 기록이 입증되고 실제 비밀·다른 자료·서비스 상태는 건드리지 않는다. 파일 한 줄 삭제는 조사 목표를 충족하지 않는다.
- **오답 복구:** 폐기된 가상 토큰·잘못 재구성한 참조·권한 부족을 구분한다. 선택 교체로 연결을 끊으면 의존성을 보여준다. 보고에는 원문 대신 가상 식별자를 남긴다.
- **전이 질문:** “현재 화면에 안 보이면 과거 유출도 취소될까?” 복사된 허구 자격 증명에 남은 효력을 확인한다.

#### M19 · 보이는 패킷, 보이지 않는 내용
- **선수 ID:** M04·M14·M15. **유형:** 통신 조사. **스토리:** 같은 시민 요청의 관찰 기록이 지점마다 달라 사고팀이 상반된 결론을 내린다.
- **첫 학습:** 패킷·관찰 지점·메타데이터·평문/암호화 구간, 전송 보호와 단말·종단 로그의 차이. **재사용 기술:** 경로·요청 식별자·서비스 주체.
- **도구:** PacketLens, TraceRoute, RequestLab, LogLens. 저장된 가상 패킷 레코드이며 실제 캡처·TLS 해독은 없다.
- **플레이 행동:** 평문/암호화 관찰 지점 비교 → 볼 수 있는 필드와 볼 수 없는 본문 구분 → 복호화 종단의 응용 로그와 상관 → 지정 전송 구간에서 사건 표식이 노출됐는지 입증한다. 전송 조치는 선택이다.
- **상태 기반 성공:** 사건 표식의 가시성과 관측 한계가 유효 증거로 연결되고 정상 통신·다른 메시지는 보존된다. 암호화 구간의 본문을 실제 해독한 것처럼 제공하지 않는다.
- **오답 복구:** HTTPS라는 이유로 모든 메타데이터가 사라진다거나 도구 버튼으로 본문을 읽는 선택은 관찰 위치 설명으로 되돌린다. 암호화 본문은 숨은 정답 텍스트로 제공하지 않는다.
- **전이 질문:** “서버 로그에 본문이 있다는 사실로 중간 관찰자도 읽었다고 할 수 있을까?” 서로 다른 관찰자의 가시성을 구분한다.

#### M20 · 서로 다른 시계의 사건
- **선수 ID:** M02·M07·M18·M19. **유형:** 사건 재구성. **스토리:** 사고팀은 토큰 사용·설정 변경·서비스 장애의 순서를 복원해야 한다.
- **첫 학습:** 로그 상관·시간 오차·증거 보존으로 사고를 재구성하기, 관측 부재와 사건 부재의 차이. **재사용 기술:** 요청·세션·패킷 메타데이터·자격 정보 이력.
- **도구:** LogLens, PacketLens, FileLens, 증거보드와 대응 카드.
- **플레이 행동:** 원본 가상 로그 보존 → 시간 오차와 사건 식별자로 상관 → 세션·토큰·패킷 기록의 타임라인 재구성 → 침투 경로와 남은 불확실성 확인. 대응 순서 실행은 선택 후속 연습이다.
- **상태 기반 성공:** 지정 사건의 접근 경로·변경 순서·불확실성이 입증되고 원본 증거와 정상 서비스가 보존된다. 자료가 없는 구간을 꾸미거나 반드시 모든 서비스를 수정해야 끝나는 구조로 만들지 않는다.
- **오답 복구:** 원본 로그 삭제를 대응으로 선택하면 분석 복사본과 원본의 역할을 설명하고 변경을 막는다. 빈 로그 구간은 미확인으로 남긴다.
- **전이 질문:** “같은 시간에 찍힌 두 로그는 같은 사건일까?” 시간 대신 상관 식별자를 추가해 가설을 갱신한다.

### 6장 · 다시 연결되는 도시: 조합·회귀·독립 조사

#### M21 · 포털 뒤의 봉인된 기록
- **선수 ID:** M05·M07·M08·M09·M10·M11·M12. **유형:** 웹 침투 체인. **스토리:** 시민 지원 포털 뒤에 감춰진 의뢰 기록이 있다. 여러 웹 진입 후보 중 유효한 경로를 골라 사건 대상 자료에 도달한다.
- **첫 학습:** 여러 웹 경계를 연결하는 접근 경로와 단계별 필요 조건. **재사용 기술:** 객체 인가와 SQLi 또는 XSS를 선택된 고정 시나리오에서 조합한다.
- **도구:** Browser, RequestLab, AccessView, QueryProbe, LogLens. 어떤 도구가 정답인지 의뢰문이 지목하지 않는다.
- **플레이 행동:** 포털 정찰 → 객체 인가·입력 처리의 진입 후보 비교 → 현재 세션·자료 권한 확인 → 선택 경로로 지정 허구 기록 최소 확보 → 정상 검색·열람·게시 제약 검증.
- **상태 기반 성공:** 목표 기록과 접근 근거가 확보되고 다른 자료·서비스 상태는 보존된다. IDOR+SQLi/XSS 조합은 권장 학습 경로이며 유효 대안으로 건너뛴 기술은 미평가다. 결함 수정은 선택이다.
- **오답 복구:** 하나의 효과만 보고 목표 자료까지 도달했다고 간주하지 않는다. 진입 성공·권한 부족·무관한 자료를 구분하고 다른 후보 경로로 전환할 수 있다.
- **전이 질문:** “같은 자료에 두 경로가 있으면 무엇으로 선택할까?” 대상 제약·필요 권한·부작용을 비교해 다음 실험을 고른다.

#### M22 · 웹에서 관리망까지
- **선수 ID:** M13·M14·M15·M16·M19·M20. **유형:** 네트워크 침투 체인. **스토리:** 외부 미리보기 서버에서 내부 정비망의 봉인된 기록까지 이어지는 길을 조사한다. 최종 관리 세션에 들어가 조작 사실을 확인해야 한다.
- **첫 학습:** 외부 진입에서 내부 목표까지 이어지는 침투 체인의 주체·권한 변화. **재사용 기술:** SSRF·서비스 노출·최소 권한·로그/패킷 상관.
- **도구:** RequestLab, NetProbe, TraceRoute, AccessView, PacketLens, LogLens.
- **플레이 행동:** 정찰 → 웹 진입 → 현재 주체·권한 확인 → 서버 경유의 가상 피벗과 내부 이동 → 지정 관리 세션·목표 기록 접근 → 정상 미리보기/정비 업무 제약 검증.
- **상태 기반 성공:** 목표 관리 세션·최소 기록·경로의 유효 증거가 있고 다른 노드·계정·시민 서비스는 보존된다. 지원된 대안 경로도 허용하며 전체 취약점 수정은 완료 조건이 아니다.
- **오답 복구:** 도달과 권한 획득을 구분하고 경로별 체크포인트를 제공한다. 망 전체 단절·범위 밖 이동·불필요한 자료 변경은 제약 실패다. 경로 차단·권한 축소는 선택 후속 연습이다.
- **전이 질문:** “경로가 달라도 같은 목표를 입증하려면 무엇이 필요할까?” 현재 권한·최소 자료·정상 기능 증거를 선택한다.

#### M23 · 안전해졌지만 멈춘 도시
- **선수 ID:** M05·M06·M07·M12·M16·M17·M18·M21·M22. **유형:** 복구·회귀 검증. **스토리:** 일괄 보안 조치 뒤 시민 사진·정비 업무·알림 동기화가 동시에 멈춘다.
- **첫 학습:** 보안 회귀와 기능 회귀·의존성·단계 조치·되돌리기. **재사용 기술:** 역할×기능 행렬·허용/거부 쌍·자격 증명 교체·업로드와 최소 권한.
- **도구:** AccessView, RequestLab, LogLens, FileLens, 필요한 경우 CredAudit. 신규 만능 복구 도구는 추가하지 않는다.
- **플레이 행동:** 변경 이력과 실패 지점 비교 → 재노출 없이 과도한 제한 완화 → 묶음 검증 → 잘못된 조치는 스냅샷을 기준으로 부분 되돌리기.
- **상태 기반 성공:** 지정된 비인가 시도는 계속 차단되고 시민·정비사·작업 계정의 정상 업무가 모두 복구된다. 보안 설정 전체 원복으로 통과하지 않는다.
- **오답 복구:** 어떤 검사가 다시 실패했는지 즉시 표시한다. 검사 통과 기록은 상태가 바뀌면 오래된 것으로 표시하고 새 실행을 요구한다.
- **전이 질문:** “한 역할의 정상 동작만 확인해도 회귀 검증이 끝났을까?” 새 역할과 경로를 검증 행렬에 추가한다.

#### M24 · 마지막 접근, 남겨진 진실
- **선수 ID:** M20·M21·M22·M23. **유형:** 독립 침투·종합 조사. **스토리:** 해람의 장애와 침투 사건 뒤에 있는 최종 기록을 독립 조사한다. 어떤 사실을 확보하고 누구에게 전달할지 플레이어가 판단한다.
- **첫 학습:** 범위 설정부터 보고까지 스스로 조사 계획을 세우는 종합 적용. **재사용 기술:** 앞 장의 웹 경계·네트워크 경로·시스템 권한·사고 증거.
- **도구:** 모든 학습 도구를 열어두되 사용 횟수를 강제하지 않는다. 시나리오가 요구하는 웹·네트워크·시스템 세 경계의 증거를 확보한다.
- **플레이 행동:** 의뢰를 조사 질문으로 분해 → 진입·조사 경로 선택 → 현재 권한·경쟁 가설 비교 → 최종 허구 기록 최소 확보 → 정상 서비스·범위 제약 검증. 근거·잔여 위험 보고와 후속 조치는 선택한다.
- **상태 기반 성공:** 최종 시나리오의 목표 사실·지정 기록이 유효 증거로 입증되고 대상/행동 제약·정상 서비스가 유지된다. 특정 체인·도구·보고 양식·모든 결함의 수정은 강제하지 않는다. 사실 발견과 후속 조치 선택은 엔딩에 반영한다.
- **오답 복구:** 기본 안내는 없고 요청형 힌트·증거 이력·부분 롤백은 유지한다. 오답 보고는 증거 부족/원인 혼동/기능 회귀로 구분해 수정 가능하게 한다.
- **전이 질문:** “실제 환경이라면 무엇을 추가로 확인해야 할까?” 허가 범위·도구 한계·실제 프로토콜/코드·환경별 검증을 게임 밖의 별도 학습으로 적는다.

## 4. 시제품 3미션의 상세 플레이 계약

M01·M05·M09는 최종 캠페인의 축소판이 아니라 복구·침투 검증·기록 조사를 검사하는 수직 샘플이다. 모두 최초/목표 상태·정상 기능·재시도를 준비하되 M05·M09의 완화·조치 후 검증은 선택 연습이다.
아래는 선택 가능한 가이드 경로이며 모든 행을 순서대로 실행할 의무는 없다. 상태 이름은 의미 계약의 예시이며 최종 키는 [기술 설계](ARCHITECTURE.md)와 맞춘다. UI가 정답 상태를 직접 쓰지 않고 조작→시뮬레이션→증거→판정으로 반영한다. ‘고정’은 선택 핀 또는 자동 감사 기록을 뜻한다.

| M01 순서 | UI와 도구 행동 | 상태·증거·완료 판정 |
|---|---|---|
| 1. 의뢰 받기 | 메일에서 정류장 대상·허용 범위·문의 열기 | 의뢰 수락과 범위 확인; 자동 복구 없음 |
| 2. 첫 관찰 | Browser 주소·링크로 안내 화면과 상태 페이지를 나란히 열기 | `stale_alias`와 `service_healthy`를 각각 관찰·고정 |
| 3. 가이드 사용 | 연결 카드의 현재/권고 대상 비교, 도움말로 대상 이름 찾기 | 낡은 별칭→폐기 서비스라는 원인 연결; 명령 철자 평가 없음 |
| 4. 조치 | 의뢰 범위의 연결 편집에서 현행 서비스 선택 | `alias_target=current_service`; 증거보드의 이전 관찰은 조치 전 표시 |
| 5. 재검증 | 일반 승객 Browser 새 조회 + 정비 상태 페이지 확인 | `arrival_fresh=true`·`service_healthy=true`, 조치 후 증거 생성 |
| 6. 독립 변형 | 새 이름의 안내판에서 강조 표시 없이 선택 연습 | 원리 재사용 관측; 건너뛰어도 복구 장면·후속 의뢰 진행 |

M01은 처음 클릭 위치를 한 번 보여주고 두 번째 관찰부터 손가락 표시를 뺀다. 마지막 변형은 의뢰·앱 목록만 남기며 첫 화면 재생은 언제든 가능하다.
시제품 M05 시작 전에 요청/응답·역할·객체의 3개 짧은 예시를 제공한다. 건너뛰기는 허용하되 `prerequisite_preset` 사용 여부만 별도로 기록한다.

| M05 순서 | UI와 도구 행동 | 상태·증거·완료 판정 |
|---|---|---|
| 1. 정상 기준 | 시민 A의 Browser 접수증 열기, RequestLab으로 요청 보기 | `actor=A,owner=A,allowed=true`; 정상 기준 증거 |
| 2. 가이드 비교 | 의뢰 범위의 허구 접수증 선택, 같은 요청의 객체만 변경 | `actor=A,owner=B,allowed=true`; 객체 경계 재현 증거 |
| 3. 원인 진단 | AccessView에서 인증 상태와 객체 허용 규칙 분리 | “로그인 여부만 확인”과 “대상 소유권 미검사”를 연결 |
| 4. 목표 확보 | 분실 보고서의 필요한 부분 읽기 또는 다른 경로의 동일 자료 확보 | `target_evidence_acquired=true`; 목표/출처/접근 맥락 입증 |
| 5. 제약 검증 | 자기 접수증·정비사 정상 열람과 대상 자료 무변경 확인 | `normal_features_preserved=true`, 과잉 수집·범위 밖 접근 없음이면 사건 완료 |
| 6. 선택 완화·전이 | 객체별 인가 적용, 자기/타인/담당 역할 요청과 청구서 변형 확인 | 완화 전후 허용/차단 검증을 별도 기록; 건너뛰어도 사건 완료 유지 |

M05는 첫 자기 요청만 자동으로 연결해 주고, 대상 단서·진입 경로·검사 순서는 플레이어에게 맡긴다. 필수 목표는 자료와 사실 확보이며 인가 수정은 완료 뒤 선택한다. 숙련자는 모든 안내를 건너뛸 수 있다.
시제품 M09 시작 예시는 검색 값이 쿼리 조건에 들어가는 작은 그림과 공개/비공개 표뿐이다. 실제 SQL 문법을 미리 익혀야 진행되게 만들지 않는다.

| M09 순서 | UI와 도구 행동 | 상태·증거·완료 판정 |
|---|---|---|
| 1. 기준 검색 | Browser 정상 검색, RequestLab 요청과 결과 고정 | 공개 결과·기준 쿼리 구조·관찰 역할 보존 |
| 2. 구조 관찰 | QueryProbe에서 제공된 입력 변형과 쿼리 트리 비교 | 값이 구조로 해석되어 결과 범위가 달라진 상태 증거 |
| 3. 가설 비교 | 후보 기록·주체·시각을 이전 접수증과 비교 | 단순 결과 증가가 아니라 같은 사건을 가리키는지 입증 |
| 4. 목표 추적 | 가상 SQLi 또는 로그/보관 경로로 지정 허구 기록 최소 확보 | `target_record_acquired=true`; 입력 방식과 무관하게 출처가 유효해야 함 |
| 5. 독립 제약 검증 | 다른 이름의 검색 대상에서 정상 검색·자료 무변경·범위 확인 | 목표 기록+유효 증거+정상 기능·제약 충족 시 사건 완료 |
| 6. 선택 완화·전이 | 매개변수 바인딩 후 정상/특수문자/구조 변형 값 재검증 | 입력이 데이터로 유지됨을 학습; 완화 생략 시에도 사건 진행 |

M09는 첫 트리 비교만 색과 설명으로 안내한다. 이후 비교 값·검사 순서는 제시하지 않고 문자열 정답표 대신 제한된 구조 모델이 결과를 계산한다. 트리를 사용하지 않은 유효 경로도 사건 통과로 인정한다.
세 샘플 모두 실패 실험은 원인 진단에 도움이 되는 기록으로 남긴다. 완주 여부·힌트 없이 독립 사용·전이 이해는 서로 다른 관측값이다. 원인 설명·선택 완화·전이 연습을 건너뛰어도 캠페인 성공을 취소하지 않는다.

### 의미 있는 대안 경로와 경계

아래는 순서만 다른 풀이가 아닌 제작 대상의 대안 상태 전이다. 모든 선택은 사건의 동일한 목표/정상 기능/범위 검사로 검증하며, 새로운 임의 동작은 지원 범위 밖이라고 명확히 알린다.

| 사건 | 경로 A | 경로 B | 통과하지 않는 우회·이유 |
|---|---|---|---|
| M01 | 잘못된 서비스 별칭 교정 | 기존 연결 대신 승인된 정상 보조 서비스로 전환 | 화면만 새 정보로 덮기: 실제 안내 갱신 중단 |
| M05 | 객체 참조 결함으로 지정 보고서 접근 | 가상 변경 이력의 동일 첨부 사본과 출처 추적 | 무관한 보고서 수집: 목표/범위 불충족; 화면 조작: 서버 자료 근거 없음 |
| M09 | 작은 쿼리 모델의 SQLi로 목표 기록 조회 | 정비 로그의 색인·보관 사본을 교차 조회 | 결과 수 증가만 확인: 지정 사건 연결 미입증; DB 수정: 무변경 제약 위반 |
| M15 | 노출 중계와 서비스 설정 결함을 통한 제한 접근 | 이전 기록의 허구 임시 자격 정보로 승인된 정비 중계 경유 | 포트만 발견: 세션/권한 미확보; 서버 종료: 정상 기능 손상 |
| M22 | 미리보기 SSRF→내부 서비스 경로→제한 관리 세션 | 작업 로그의 허구 자격 단서→정비 중계→동일 관리 자료 | 내부 도달만 확인: 목표 권한 미입증; 망 전체 개방: 범위/기능 제약 위반 |

M21·M22의 가상 침투 조사에는 정찰→서비스/입력 결함에 의한 진입→현재 권한 확인→허용 범위 내 내부 이동 가능성→목표·정상 기능 검증을 담는다. 특정 체인을 직접 밟지 않고 설정·로그·권한 감사로 동일 상태를 입증해도 인정한다.
침투·조사 완료와 결함 완화를 별도 기록한다. 복구 사건에서 보완 통제로 목표를 충족했지만 근본 결함이 남으면 ‘복구 성공·추가 조치 필요’로 표시한다. 미평가 기술·미실시 완화·잔여 위험을 혼동하지 않는다.

## 5. 힌트 4단계·오답·복습

1. **목표 환기:** 지금 확보할 접근·사실·자료 또는 복구할 업무와 아직 모르는 질문을 보여준다. 정답 도구는 지목하지 않는다.
2. **증거 위치:** 확인할 앱·로그 범위·비교 역할을 알려준다. 어떤 결과가 나와야 하는지는 말하지 않는다.
3. **비교 실험:** 한 번에 바꿀 요소와 유지할 기준을 제안한다. 요청·정책은 플레이어가 선택한다.
4. **작동 예시:** 현재 정답의 자동 실행 대신 작은 별도 예시를 보여준다. 본 사건의 다음 행동을 명시 요청한 경우 한 단계 안내하며 사용 사실을 기록한다.

힌트는 요청형이고 시간 경과만으로 강제로 뜨지 않는다. 장시간 무상태·동일 오류 반복 시 닫을 수 있는 도움 제안을 하되 긴장 연출은 줄일 수 있다.
오답은 구문 오류, 증거 부족, 원인 혼동, 조치 미흡, 정상 기능 손상으로 구분한다. “틀렸다” 대신 관찰된 상태와 아직 충족하지 않은 조건을 보여준다.
구문 오류에는 현재 지원되는 옵션·토큰 위치를 표시하고 명령을 실행하지 않는다. 시험적 실패가 캠페인 영구 손실이나 실제 시간의 장기 대기로 이어지지 않는다.
복습은 같은 문자열 재입력 대신 파일·계정·엔드포인트 이름과 관찰 지점을 바꾸고, 핵심 원리·해결 가능성·정상 기능 검사는 유지한다.
한 미션의 독립 사용이 막히면 관련 앞선 사례로 돌아갈 수 있지만 미션 보상·도구·이미 확보한 증거를 회수하지 않는다.

## 6. 실제 개념과 게임 단순화의 경계

| 주제 | 남길 실제 개념 | 명시할 게임 단순화·금지할 오개념 |
|---|---|---|
| Linux·네트워크 | 경로·권한·주체·포트·관찰 지점 | 작은 파일 트리·고정 서비스, 실제 셸/OS/nmap 전체가 아님; 열림=취약 아님 |
| HTTP·인가 | 요청·응답·상태 변경·객체별 권한 | HTTP 일부 필드만 모형화; 숨긴 버튼/추측 어려운 ID=인가 아님 |
| 인증·세션·CSRF | 로그인·요청 권한·무효화·의도 구별 | 가상 시계·간소한 토큰; 화면 로그아웃/토큰 존재만으로 보호 완료 아님 |
| SQLi | 값이 쿼리 구조가 되는 경계와 매개변수화 | 작은 쿼리 트리·고정 허구 테이블; 실제 DB별 문법/우회 전체를 모사하지 않음 |
| XSS | 비신뢰 데이터의 출력 맥락·효과 | 미리 정의한 DOM/효과만 모사, JavaScript 실행 없음; 모든 맥락의 단일 인코딩 아님 |
| 경로·업로드·명령 | 정규화된 범위·저장/실행 분리·인자 경계 | 가상 파일·명령만; 문자열 금지 목록 하나가 모든 결함 해결책 아님 |
| SSRF·내부망 | 요청 주체·목적지·최종 경로·최소 권한 | 내부 노드 그래프, DNS/재지정 일부; 내부 주소 접근이 곧 관리자 권한 아님 |
| 암호 감사·비밀 | 온라인/오프라인 차이·노출 후 폐기/교체([비밀번호 저장](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), [비밀 관리](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html)) | 작은 허구 사전·비용 모형, 실제 시간 추정 없음; 사전 미검출=안전 아님 |
| 패킷·사고 대응 | 관측 위치·평문/암호문·증거/추정 구별([TLS 1.3 명세](https://www.rfc-editor.org/rfc/rfc8446.html)) | 합성 패킷·로그; HTTPS 본문 임의 해독 없음, 로그 부재=사건 부재 아님 |

이 표는 구현자가 지켜야 할 교육 계약이다. 플레이어에게는 현재 사건 옆의 짧은 설명과 종료 후 ‘현실에서는 무엇이 더 필요한가’ 카드로 나눠 보여준다.
개념 설명은 [OWASP WSTG](https://owasp.org/www-project-web-security-testing-guide/)의 테스트 분류와 [PortSwigger 학습 경로](https://portswigger.net/web-security/learning-paths)를 참조하고, 파일·명령 도입의 단계성은 [Bandit](https://overthewire.org/wargames/bandit/)을 참고한다. 이 게임은 해당 기관의 인증·제휴 교육이 아니다.
상세 검수 출처: [인가](https://portswigger.net/web-security/access-control), [인증](https://portswigger.net/web-security/authentication), [로그아웃](https://wstg.owasp.org/v4.2/4-Web_Application_Security_Testing/06-Session_Management_Testing/06-Testing_for_Logout_Functionality/), [CSRF](https://portswigger.net/web-security/csrf), [SQLi](https://portswigger.net/web-security/sql-injection), [XSS](https://portswigger.net/web-security/cross-site-scripting), [경로 탐색](https://portswigger.net/web-security/file-path-traversal), [업로드](https://portswigger.net/web-security/file-upload), [명령 삽입](https://portswigger.net/web-security/os-command-injection), [SSRF](https://portswigger.net/web-security/ssrf). 2026-11-04 페이지 확인. 문제·문장·자산은 복제하지 않는다.

## 7. 전이 평가·학습 지표·정확성 검수

평가는 미션 완주, 기술 학습 관측, 원인 설명, 이름·표면이 바뀐 전이 행동을 분리한다. 기술을 사용하지 않았거나 선택 평가를 건너뛴 경우 0점이 아니라 ‘미평가’다. 단순 철자·속도·실패 횟수로 이해도를 판단하지 않는다.
전이 문항은 카드별 질문에서 출발하되 새 역할/경로/입력 위치로 바꾼 행동 문제다. 설명만 맞히고 확인하지 않은 경우와 올바르게 실험했지만 용어가 서툰 경우를 구분한다.
제안 루브릭: 0=근거 없이 추측, 1=힌트로 증거 발견, 2=독립 비교와 원인 설명, 3=새 맥락에서 적용하고 정상 기능·한계를 검증. 한 번의 3점으로 숙련을 확정하지 않는다.
로컬 지표는 미션 ID·콘텐츠 버전·사건 유형·독립 시도 여부·힌트 최고 단계·목표/제약 검사·선택 완화 여부·전이 루브릭·활성 플레이 시간이다. 완화를 안 한 침투 사건을 미완료로 집계하지 않는다. 입력 원문·실제 개인정보·전체 키 입력은 수집하지 않는다.
시간은 난이도 조정 자료이며 성적에 합산하지 않는다. 쉬운 길을 안내받은 완주는 실패가 아니지만 독립 이해와 같은 수치로 합치지 않는다.
입문자 5명 내외의 초기 관찰은 사용성 탐색이다. 4명 이상이 추가 구두 안내 없이 M01을 완료하고, 3명 이상이 M05 또는 M09 변형에서 원리를 적용하면 확장 후보로 삼는다. 통계적 효과 입증으로 발표하지 않는다.
절반 이상이 철자·창 전환에서 2분 이상 멈추면 입력과 UI를 먼저 고친다. 절반 이상이 완주했지만 원인을 설명하지 못하면 단서·반응·전이 문제를 다시 설계한다.
장별 재사용 검사는 M04→M05(HTTP), M05→M07/M16(인가), M09→M13/M21(구조 경계), M14→M15/M22(관찰 지점), M19→M20/M24(증거 한계)로 추적한다.

보안 정확성 검수는 콘텐츠 작성자와 검토자를 분리하며, 후속 구현 전 아래 순서로 수행한다. 현재 이 절차의 실행 결과를 PASS로 주장하지 않는다.
1. 미션별 학습 주장·지원 모형·지원하지 않는 실제 동작·공식 근거 링크를 콘텐츠 명세에 기록한다. 버전 고정 가능한 WSTG 문서는 버전 경로를 남긴다.
2. 독립 검토자는 원인/완화의 연결, 위 표의 오개념, 인증과 인가·주체와 경로·암호화와 종단 로그의 혼동을 확인한다. 출처가 없는 세부 주장은 유보·수정한다.
3. 구현 담당자는 정상 기준·목표 접근/사실 입증·범위 제약·오답 경로·동등한 대안의 상태 검사를 만든다. 복구/선택 완화에서는 조치 전후 허용·차단과 정상 기능 회귀를 추가한다. 정답 입력·필수 패치 하드코딩 여부도 확인한다.
4. 경계 검사는 모든 명령·브라우저 주소·파일 작업이 가상 ID로만 해석되는지, 실제 프로세스/네트워크/임의 스크립트 경로가 없는지 정적·런타임으로 확인한다.
5. 교육 검토자는 실제 개념/게임 단순화 카드와 전이 변형을 읽고, 플레이테스터는 설명 없이 실험한다. 오해가 반복되면 난이도보다 모형·피드백을 먼저 수정한다.
6. 미션 개정 시 영향받는 선수/재사용 미션과 저장 상태를 함께 검토하고, 콘텐츠 버전·검토자·검사 결과·남은 한계를 남긴다. 결함 하나의 수정으로 전체 교육 품질을 통과 처리하지 않는다.

이 문서는 24개 사건의 제작 계약이다. 세부 대사·실제 화면·모형 코드·설치 빌드·사람 대상 학습 평가는 후속 제작이며, 구현 순서와 출시 조건은 [개발 순서와 검증](ROADMAP_AND_QA.md)을 따른다.
