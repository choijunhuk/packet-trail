# 전체 캠페인 QA·완료 판정 계약

기준일: 2026-11-05 · 작업 브랜치: `feat/full-campaign` · 범위: 기존 기획의 전체 제품 검증 계약.

기능 기준은 [PROJECT_PLAN](../../PROJECT_PLAN.md), [CURRICULUM](../CURRICULUM.md), [분량·스토리](../PACING_AND_STORY.md), [플랫폼·언어·음향](../PLATFORMS_LANGUAGES_AUDIO.md), [화면 설계](../../DESIGN.md)다. 이 문서는 검증할 동작과 증거를 정하며 콘텐츠·공개 API의 별도 원본을 만들지 않는다. 캠페인 schema/API는 [캠페인 계약](campaign-contract.md)과 동기화한다.

## 1. 이번 작업의 완료 범위

사용자는 첫 실행 묶음에서 멈추지 않고 **6장 메인24+선택4, 작은 3D 작업실, 여러 터미널·도구·가상 웹, 6개 언어, OST 7큐, Windows/macOS/Linux 패키지**까지 제작하도록 요청했다. 첫 미션·3미션·MVP 완료는 중간 진척이며 전체 완료가 아니다.

- `main 939bbcc`의 첫 실행판 `v0.1.1-dev`와 기존 사용자 앱·저장·`.serena/`를 보존한다.
- 기존 core/save 336·native UI 32 검사는 회귀 기준이다. 과거 통과 횟수를 새 캠페인·3D·번역·음악의 검증 결과로 전용하지 않는다.
- 코드·콘텐츠·자산 제작과 가능한 자동/GUI/플랫폼 검증은 계속 진행한다. 물리 IME·사람의 8~12시간 플레이·재미·외부 공증이 미실행이라는 이유로 사용자 피드백을 기다리며 제작을 중단하지 않는다.
- 미실행 항목은 결과에서 `NOT_RUN`과 이유를 남긴다. 전범위 구현과 사람의 플레이타임/학습 효과 확인, 패키지 생성과 실제 OS 실행, ad-hoc 서명과 공증을 각각 다른 주장으로 기록한다.
- 기능 누락을 문서에서 후속으로 옮기거나 고유한 퍼즐을 파일명만 다른 회수 작업으로 바꿔 전체 완료를 주장하지 않는다. 현재 제작 manifest의 선택4는 S01/S02/R01/P01이다. 기존 기획이 허용한 소형 모형 검증 후 S03/S04 교체를 적용하는 것으로, R01/P01의 실제 의미·경계 검사를 생략한 채 이름만 바꾸는 것은 수용하지 않는다. 모바일·AD·클라우드·무선/IoT 및 독립 후속 캠페인은 별도 범위다.

## 2. 검증 층과 증거

| 표시 | 증명하는 것 | 대신 증명하지 않는 것 |
|---|---|---|
| A · 자동 | 콘텐츠/schema·코어·실제 Action 재생·저장·번역/자산 manifest·export·부정 gate | 실제 IME, 청취 품질, 재미, 사람 플레이 시간 |
| G · GUI | 실제 앱 장면에서 입력·창·도구·방 전환·목표 표시·저장 재개 | 다른 OS의 동작, 물리 키보드 IME, 사람의 이해·선호 |
| O · 실제 OS | 해당 OS/CPU/그래픽·창·파일·입력·오디오·배포 환경에서 최종 파일 실행 | 검증하지 않은 OS/배포판/아키텍처 전체 |
| H · 사람 | 처음 보는 사람이 스스로 판단하는지, 이야기·도구 재사용·청취·페이싱 | 자동 회귀 전체, 통계적 교육 효과 |

각 결과는 `feature_id`, 대상 commit/콘텐츠 버전, 명령 또는 조작, 환경(OS/CPU/엔진/locale), 검사 수와 실패, `PASS/FAIL/NOT_RUN`, 산출물 경로·해시, 남은 한계를 연결한다. 계획표의 행이나 JSON 파싱 성공만으로 `PASS`를 채우지 않는다. 재생 결과는 원본 Action→공통 판정기를 거쳐야 하며 디버그 완료 플래그를 직접 세팅한 실행은 해법 증거가 아니다.

검사는 **콘텐츠·코어·저장·UI가 연결된 묶음**에서 수행한다. 작성 중인 작업자의 함수마다 검사/재검토를 요구하지 않는다. 이 문서 작성 단계에서는 전체 도구·Godot·gate를 실행하지 않는다.

## 3. 모든 사건에 적용할 공통 검사

1. 초기 상태는 미완료다. 빈 목표·미등록 goal/Action·누락/잘못된 참조·불가능한 필수 경로는 콘텐츠 오류로 거절한다.
2. 정상 해법은 실제 상태·유효 근거·보존/정상 기능 제약을 함께 만족한다. 이름만 같은 자료, 같은 ID의 변조 본문·허용 밖 출처, 무관한 200 응답·열린 포트는 성공을 만들지 않는다.
3. 등록된 다른 유효 경로도 같은 의미의 목표를 충족하면 통과한다. 도구 사용 플래그·명령 순서·튜토리얼·증거 pin·설명 퀴즈는 캠페인 필수 조건이 아니다. 이번 제작 묶음은 전체 28사건×2해법을 각각 새 엔진에서 재생한다. 선수 사건도 실제 해법으로 열고 완료 플래그를 주입하지 않는다. M01/M05/M09/M15/M22의 기존 A/B를 포함하며 단순 명령 순서 변경만 다른 해법으로 세지 않는다.
4. 대표 오답·권한 부족·대상 범위 위반·정상 서비스 파괴·오래된 관찰을 검사한다. 과거 사실은 보존하고 현재 충족은 현재 상태로 확인한다. 연속 관찰/무관한 로그가 이전 근거를 지우지 않는다.
5. 실패한 변경은 부분 적용되지 않는다. 원격 서비스가 관찰한 거절 응답·경보는 유효한 도메인 결과이며 로컬 구문 오류와 구분한다.
6. 완료 표시와 답장·도구/자료·다음 단서는 미완료→완료 전이에서 한 번만 반영된다. 조회·재회수·완료 저장 복원·사건 재방문은 보상을 중복 적용하지 않는다.
7. 재시작/체크포인트/저장 왕복 후 해결 가능성과 진행·선택·보관 자료가 유지된다. 선택 사건·선택 평가 미실시로 메인 스토리를 막지 않는다.

### OST 7큐

대상은 A01 Signal Home, A02 First Connection, A03 Hidden Route, A04 Packet Flow, A05 Raised Alert, A06 Broken Pattern, A07 Clear Channel이다. 원래 7큐/약17~24분은 제작 목표이며 음원 재생 길이와 합계를 실제 파일로 기록한다.

## 8. 캠페인 API·fixture 동기화와 최종 판정

캠페인 계약 초안이 정해지면 다음 항목을 한 묶음으로 확인한다. 기존 M01의 `execute/submit_password/browse/collect_web/get_view/export_snapshot/restore_snapshot/save/load/recover/reset` 호출부와 336/32 회귀는 유지하거나 명시적인 호환 어댑터·회귀로 변경한다.

- 새 사건 선택/시작/완료/다음 사건·선택 사건/선택 생략/엔딩과 선수 해금의 안정 ID.
- 도구/명령/브라우저가 공유하는 Action·요청 주체/세션·가상 경로/정책·증거 참조와 현재 목표/제약 평가.
- M06/M07/M08/M12 등의 인증 제한·회복/세션 생애/출처·세션 결부/업로드 처리 상태가 실제 요청 결과를 바꾼다는 계약. 공통 Challenge 성공으로 기록/fact를 지급하거나 정책 bool만 바꾼 것으로 해당 동작을 대신하지 않는다.
- request의 관찰 주체·웹 인증 세션·요청 출처와 응답 status/처리 trace 등 필요한 의미 결과. RequestLab/curl이 가상 SSH 주체를 사용하는 경우 `actor_context=terminal`로 드러내며, Browser의 쿠키 컨텍스트와 구분한다. SSH 인증이 쿠키로 자동 복제되거나 다른 origin의 세션을 바꾸지 않아야 한다. 화면 문구 비교나 별도 도구 정답 분기로 이 정보의 부재를 보완하지 않는다.
