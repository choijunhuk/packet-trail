# 캠페인 재설계 브리프 · 침투·방어·추적

기준 작업 트리: `packet-trail-expansion`, 기준 커밋 `0565166`. 이번 산출물은 **설계와 계약 요구**다. 제품 코드·캠페인 JSON·원본 자산·세이브는 수정하지 않는다. 구현·실행 결과는 후속 묶음에서 별도로 기록한다.

사용자는 침투편 개선과 독립 방어·추적 확장을 승인했다. 침투 메인24+선택4를 유지하고 방어8(D01~D08)·추적8(T01~T08)로 만드는 수량은 제작자의 이번 범위 권고다. 세 편은 자기 온보딩·발단·위기·결말을 갖고, 다른 편의 진도·세이브·학습 시험으로 잠그지 않는다. 같은 도시와 인물은 공유하되 타편 플레이를 이미 일어난 유일한 역사로 단정하지 않는다.

## 1. R2에 대한 실질 교정

[전체 감사 R2](../reviews/CLAUDE_FULL_AUDIT_20261105.md#r2-필수-근거-수집의-반복과-최종-종합-사건의-계약-격차)의 핵심은 필수 자료 수를 늘린 것이 판단의 깊이가 되지 않았다는 점이다. 89개 중 66개 exhibit에 붙은 공통 `ssh → cat → compare/trace → exit` 경로는 제거 대상이다. 이름·그림·주소·도구 ID만 바꾸어 남기지 않는다.

| 현재 문제 | 이번 설계의 처리 | 유지할 것 |
|---|---|---|
| 동일한 문서 두 줄을 다시 입력해야 생기는 필수 exhibit | 공통 exhibit 목표를 기본 캠페인에서 해제. 원장은 원인·경로를 추론하는 선택 자료로 남김 | 사본·출처 보존, 필요한 경우 실제 관찰 확보 |
| 별도 원장에 로그인하는 것이 사건 길이의 대부분 | 이미 얻은 세션·관찰을 재사용. 새 연결은 신뢰 경계나 관찰 지점이 달라질 때만 필요 | 현재 actor·호스트·권한·직접 라우팅의 일관성 |
| compare와 trace가 다른 56개 fixture를 의미 다양성으로 셈 | 판단·실패·상태 전이가 다른지를 검토. 입력 UI가 다르다는 이유만으로 대안 인정 안 함 | 정상/부정/동등 해법의 실제 재생 |
| 자료를 얻으면 현재 경계 검증까지 한 것으로 간주 | 현재 동작이 목표인 사건은 그 시점의 요청·경로·서비스 결과로 판정 | 과거 사실의 유효한 보존 사본 |
| M24가 이전 사건 완료와 문장 대조로 종합을 대체 | M24 안에서 웹·라우팅·서비스 권한 세 경계를 새로 확인 | 지원한 두 경로 중 자유 선택 |
| R01이 XOR 단어 복원에 머묾 | 작은 의사코드의 조건·분기·호출 흐름을 실행/관찰하는 퍼즐 | 실제 바이너리·CPU 전체를 재현하지 않는 범위 |

필수 자료 수에 새 최저치를 두지 않는다. 기본은 핵심 목표 1개와 사건에 필요한 현재 상태 제약이다. 독립 자료가 필요한 때는 “그 자료 없이는 어떤 두 가설이 구분되지 않는가”를 먼저 적는다. 답이 없으면 선택 기록으로 내린다.

반복을 줄인 자리는 요청자·객체·관찰 위치·정책·가용성·정상 업무 사이의 선택으로 채운다. 성공의 손맛은 막혔던 길의 개방, 잘못된 가설의 반증, 피해를 줄인 정밀 대응, 다음 관찰의 적중에서 만든다. 강제 명령 수·읽기 분량·대기 시간을 목표로 삼지 않는다.

## 2. 공통 판정과 정보 경계

- **침투:** 유효한 목표 접근/회수 + 대상·행동 제약 + 필요한 현재 경계 검증. 특정 도구·명령·튜토리얼·노트 핀은 조건이 아니다.
- **방어:** 모델링한 위협 경로 억제 + 지정 정상 업무 성공 + 자료 보존 + 사건별 복구/격리 범위. 공격 요청이 사라졌다는 사실만으로 통과하지 않는다.
- 정상/위협 시나리오의 구분은 검증용 기대값이다. 실행 정책이 숨은 `is_attacker`/정답 flag를 읽어 차단하지 않으며 실제 요청·현재 actor·객체·권한·경로·빈도 조건으로 결과를 만든다.
- **추적:** 현재 관찰로 지지되는 연결 + 필요한 후속 관측 + 반증·미확정 범위의 정직한 인계. 내부 범인 이름과의 문자열 일치는 조건이 아니다.
- 관측 결과는 요청자·관찰 지점·대상·상태 시점·출처를 갖는다. 정책/경로가 바뀌면 관련된 **현재 상태 주장**만 다시 확인한다. 무관한 파일 읽기 때문에 전체 증거를 버리지 않는다.
- 내부 ground truth, 플레이어가 본 관측, 플레이어의 가설을 분리한다. 가설 저장으로 세계의 사실이 생기지 않는다. 관찰되지 않은 정답으로 즉시 칭찬·벌점을 주지 않는다.
- 모든 접속·대응·관측은 내부 가상 세계만 바꾼다. 실제 호스트 프로세스 실행·외부 네트워크 공격·실사용자 추적을 연결하지 않는다.
- 원자료에는 실제 사건의 요청·행·소유 관계·시각을 보여준다. `goal/fact/model` 내부 ID·직렬화 manifest를 정답 문서로 보여 주지 않는다. 사람용 설명은 한국어/영어로 작성하고 경로·명령·원자료 토큰만 안정적으로 유지한다.
- 잘못된 선택은 무엇이 막혔고 무엇이 남았는지 알려준다. 오타·읽기·창 이동·실제 경과 시간에는 위험 벌점을 주지 않는다. 실패 뒤 유효 세션·다른 허용 경로·범위가 한정된 재시도를 남긴다.

아래 A/B는 서로 다른 신뢰 경계·관찰·대응을 쓰는 대표 해법이다. 같은 요청을 GUI와 터미널에서 보내는 것은 같은 해법의 두 입력 표면이지, 독립 해법 두 개가 아니다. 상태와 제약이 맞는 다른 지원 조합도 인정한다.

| **T01 한 주소의 여러 그림자 · 배우기** | 같은 IP가 같은 사람인가. 제한된 계정/세션 관찰 / 중계 연결 시각·수신 기록 | 공유 출처 뒤 복수 세션 가능성과 다음 관찰 지점 확보; 개인 정체는 미확정 | 이름 클릭은 정답 판정 안 함. 민서는 현재 관찰이 지지/반박하는 연결만 설명 |
| **T02 맞지 않는 두 시계 · 활용** | 사건 순서인가 시계 오차인가. 공통 기준 이벤트 / 서명 인계의 시간 구간 | 오차를 반영한 가능한 순서·불가능한 순서를 구분 | 정확한 초를 모르는 자료에 정확한 시각을 단정하면 근거가 부족하다고 표시 |
| **T03 복사된 기록의 출처 · 활용** | 변조·재배포·수집 누락 중 무엇이 차이를 설명하는가. 원본/사본 인계 관계 / 독립 수신자의 기록 | 어떤 자료가 어디에서 왔는지와 신뢰 한계 연결 | 해시 일치만으로 내용이 진실이라 단정 안 함. 민서는 출처와 진실성을 구분 |
| **T04 다음 접속을 기다리는 곳 · 활용** | 어느 지점의 새 관측이 후보를 가장 잘 구분하는가. 중계 경계 관찰 / 승인된 종단의 제한 계측 | 선택한 후속 관측으로 후보 연결 하나를 강화/반증하고 다음 목표 확보 | 숨은 범인의 위치를 찍는 정답표 없음. 같은 정보만 다시 모으면 새 연결은 생기지 않음 |
| **T05 도난당한 이름 · 위기** | 계정 주인과 실제 세션 사용자를 같은 것으로 볼 수 있는가. 세션 생애/장치·경로 / 위임·폐기 기록과 독립 접속 | 탈취/공유/정상 사용 중 남는 가설과 필요한 다음 관측을 명시 | 계정명만 보고 사람을 추궁하면 NPC는 근거를 요구하되 내부 정답으로 즉시 틀렸다고 하지 않음 |
| **T06 보이지 않는 구간 · 위기** | 암호화·누락 뒤에서 무엇까지 연결할 수 있는가. 메타데이터와 종단 허가 / 중계 양끝의 시간·크기 구간 | 내용 미확정 상태에서도 지지되는 이동 연결과 관측 공백 확보 | TLS 본문 해독·모든 메타데이터 소멸 둘 다 아님. 민서는 확인 범위까지만 인계 |
| **T07 맞는 가설을 버릴 때 · 위기·반증** | 기존 가설과 충돌한 새 자료를 어떻게 다룰까. 독립 출처 재관측 / 경쟁 가설이 예측한 다음 이벤트 비교 | 반증된 edge는 이력을 남겨 철회, 남은 후보와 다음 인계 경로 갱신 | 예전 가설에 맞춰 새 기록을 무시하거나 원자료 삭제하면 실패. 반증 자체는 진전으로 반응 |
| **T08 마지막 연결의 범위 · 종결** | 무엇을 입증했고 무엇은 모르는가. 서로 다른 출처의 경로 연결 / 관측 예측을 검증한 최소 연결망 | 요구된 전송/접속 연결·반증·출처·미확정 구간과 후속 인계를 완성 | 범인 실명 퀴즈·막연한 “모름” 모두 종결 조건 아님. 확인된 중계/권한 연결 범위에 맞는 독립 결말 |

추적 종료는 같은 공개 관측에 양립하는 행위자 후보가 둘이어도 가능하다. 다만 사건이 요구한 연결과 후속 관측을 확보해야 한다. 확인 불가능한 실명 대신 “어느 세션이 어느 경계를 통과했고, 어느 주장은 반박되었는가”로 끝낸다.

## 6. 먼저 구현할 대표 사건 계약 — 편당2개

아래 기호는 계약 요구를 설명하는 이름이며 최종 JSON 필드명은 아키텍처 담당이 정한다. 새 프레임워크를 먼저 완성하라는 요청이 아니다. 기존 상태·요청·서비스·관측을 작은 조합으로 확장하고, 두 표면이 같은 판정기를 사용한다.

### I-A · M05: 객체 권한과 대안 자료 접근

- **초기 상태:** 자기 접수 A, 대상 C731, 무관한 접수 Z; 웹 세션의 actor/소유자/역할, 별도 첨부 서비스의 제한 위임. 자기/담당자 정상 업무가 있다. 대상 보고서의 canonical 내용·허용 출처를 등록한다.
- **행동:** 조회·객체 참조 변경·현재 actor 확인·제한 위임 요청·대상 회수. 명령 이름이 아니라 동일 요청 행위로 호출할 수 있어야 한다.
- **A:** 자기 객체를 기준으로 C731 요청 → 취약한 객체 인가에서 대상 접근 → 최소 사본 회수. **B:** 첨부 서비스의 적법 위임 scope 확인 → 같은 대상 사본 접근 → 회수. B에 IDOR 호출 기록은 필요 없다.
- **관측:** 각 응답의 requester/object owner/허용 결과와 공개 가능한 출처. 요청하지 않은 Z의 내용은 자동 표시하지 않는다.
- **판정:** `valid_target_copy && original_preserved && unrelated_unchanged && normal_workflows_ok`. 객체 인가 결함 학습은 실제 비교를 했을 때만 별도 관찰한다.
- **악수:** 로그아웃/전체 차단/무관한 Z 회수/ID만 같은 위조 본문. 어디가 실패했는지는 현재 허용·거부·대상 상태로 설명한다.
- **필요 계약:** 실제 actor/object 위임 모델, 자료 동등성, 정상 업무 probe. 고정 `answer`나 추가 exhibit fact를 입력하면 대상 권한을 주는 지름길은 금지한다.

### I-B · M24: 현재의 세 경계

- **초기 상태:** 서로 다른 웹 역할, 외부/중계/내부 노드, 열린/필터링 서비스, 제한 관리 자격. 최종 지시의 최소 자료는 두 유효 출처를 갖는다. 과거 사례의 완료 fact는 현재 요청 성공을 만들지 않는다.
- **A:** 웹 actor/객체 경계 확인 → 서버 요청 주체로 내부 경로 확인 → 제한 서비스 인증/자료 읽기. **B:** 정비 actor의 승인 경로 → 좁은 중계/서비스 인증 → 같은 자료 위임; 웹 경계는 독립 probe로 현재 동작 확인.
- **공통 필수 관측:** 웹의 정상/비인가 요청 차이, 현재 vantage에서 내부 목적지의 실제 도달, 현재 서비스 자격의 허용/범위 밖 거부. 세 종류가 각각 있어야 하며 사본만으로 대체하지 않는다.
- **웹 차이의 의미:** A는 현재 actor와 다른 소유 객체가 실제로 반환되는 결함을 입증할 수 있고, B는 좁은 적법 위임의 허용/범위 밖 거부를 입증할 수 있다. 세 종류의 취약점을 모두 공격하거나 세 종류의 정책을 모두 패치하는 것이 필수라는 뜻은 아니다.
- **현재성:** 경로/서비스/권한을 바꾸면 관련 probe의 결과를 다시 확인한다. 다른 창 열기나 무관한 파일 읽기로 전체를 무효화하지 않는다.
- **판정:** `web_boundary_now && route_boundary_now && service_scope_now && valid_target_copy && preservation`. 내부 조건은 actor·대상·관찰 위치·현재 관련 상태를 검증하며 호출 도구 이름은 보지 않는다.
- **악수:** 과거 로그 세 장 제출, 존재하지 않는 route 가정, 포트 열림=읽기 권한, 관리자 전체 권한, 서비스 종료. 해당 실제 응답과 남은 경계를 보여 준다.
- **필요 계약:** 실제 요청·라우팅·서비스·권한 결과로 생성되는 현재 관측, 관련 상태의 좁은 유효성, 유효 사본 대안. 새 compare/trace 문장 3개를 만든 것으로 충족 처리하지 않는다.

### D-A · D01: 정상 업무를 살리는 인가 교정

- **초기 상태:** 접수 API와 첨부 업무, 정상 시민 두 명·담당 정비사·비인가 actor. 공격/정상 요청을 같은 UI에서 재생할 수 있고 D01 자체가 actor·객체·허용 결과를 소개한다.
- **A:** 접수 API의 소유자/담당자 검사 적용. **B:** 원래의 노출 경로는 제한하되 검증된 업무 gateway의 객체별 위임 경로로 정상 업무를 이관.
- **판정:** 비인가 actor→C731 거부, 시민A→자기 접수 성공, 시민B→자기 접수 성공, 정비사→담당 접수 성공, 원본/다른 자료 보존. 경로가 다르더라도 같은 업무 결과면 인정한다.
- **위험 선택:** 전체 API 종료는 공격도 막지만 시민 업무가 실패하므로 완료하지 않는다. 정비사 전원 관리자 승격도 범위 실패다.
- **복구:** 적용 전 정책 snapshot과 변경 단위를 제공한다. 잘못된 범위만 되돌려 정상 경로를 회복하고 공격 경로를 다시 확인할 수 있다.
- **관측/반응:** 현재 성공/거부 응답을 보여 주고 도윤은 어떤 시민 업무가 살아 있는지 말한다. “이 정책 카드가 정답”이라는 외부 평가를 주지 않는다.
- **필요 계약:** 정밀 actor/object 정책 또는 승인 경로 대안, 명시적 정상 업무 시나리오, 비파괴 정책 rollback, 격리와 최종 복구 상태 구분.

### D-B · D07: 부분 롤백과 독립 폐기 상태

- **초기 상태:** 의심 내부 요청과 정상 알림, 잘못 적용한 긴급 egress 규칙, 이미 폐기한 노출 세션. 공격 억제와 알림 가용성이 서로 다른 제약을 가진다.
- **A:** 의심 목적지/작업자만 격리 → 잘못된 알림 규칙만 부분 rollback → 정상 알림·공격 경로 재관찰. **B:** 승인 대기 서비스로 알림 이관 → 원래 위험 작업 경로를 계속 격리 → 같은 업무/보안 행렬 확인.
- **판정:** 정상 알림과 정비 업무 성공, 비인가 내부 읽기 거부, 폐기 세션 거부, 원본 보존. 일부 임시 중단은 의뢰에 표시한 범위에서만 허용하고 최종 복구와 혼동하지 않는다.
- **악수:** 전체 예전 snapshot 복원으로 폐기 자격이 살아남, 모든 egress 종료, 허용 proxy가 범용 우회가 됨. 현재 probe가 정확히 반박하는 결과만 알려 준다.
- **필요 계약:** 정책 snapshot/부분 rollback과 자격 폐기 이력 분리, 대체 경로의 업무 동등성, 현재 공격/업무 요청. 무제한 이벤트 소싱 엔진은 필요 없다.

### T-A · T01: 공유 IP와 관측 선택

- **초기 공개 관측:** 같은 출처 IP를 쓰는 세션 S1/S2, 겹치는 시간 구간, 하나의 중계 수신 기록. IP만으로 사람/세션 동일성을 알 수 없다. 내부 행위자 ID는 UI에 전달하지 않는다.
- **A:** 허가된 세션 이력의 다음 인증/접속 관찰. **B:** 중계 양끝의 제한 연결 관찰. 플레이어는 어떤 새 관측이 두 가설을 구분할지 선택한다.
- **가설:** “같은 IP이므로 같은 사용자”는 현재 `underdetermined`; “S1→릴레이 전송”은 해당 관측이 확보되면 `supported`. 실제 숨은 행위자가 누구인지는 피드백 판단에 사용하지 않는다.
- **후속 관측:** S1/S2의 각기 다른 세션 표식이 나타나면 동일 세션 단정을 반박할 수 있다. 같은 데이터만 다시 읽어 가설 상태를 바꾸지 않는다.
- **판정:** 관측이 지지하는 전송/세션 연결과 다음 조사 지점을 확보하고 실명 단정을 보류. 범인 후보를 전부 나열하거나 무조건 “모름”만 고르면 완료하지 않는다.
- **필요 계약:** provenance·관찰 위치·시간 구간을 가진 관측, 가설과 사실 분리, 실제 관측을 추가하는 선택 행동, 가시 정보만 사용하는 반증/지원 판정.

### T-B · T07: 새 반증이 들어온 뒤의 갱신

- **초기 상태:** T01 지식 없이도 이해 가능한 짧은 사건 요약과 후보 연결 2개, 시계 오차가 있는 원장, 이전 수집본의 보존 이력. 한 후보는 새 관측이 오기 전까지 다른 후보와 양립한다.
- **A:** 독립 기준 이벤트를 수집해 시각 구간을 좁힘. **B:** 각 후보가 예측한 다음 중계/종단 관측 중 하나를 허가 범위에서 수집.
- **반응:** 새 관측이 지지/반박하는 edge만 갱신한다. 내부 정답과 다른 후보를 골랐다는 이유로 관측 전에 “틀림”을 주지 않는다. 틀린 가설을 세운 이력도 지우지 않는다.
- **판정:** 반증된 연결을 철회하고 지지되는 최소 연결망과 후속 인계를 남김. 알 수 없는 구간은 unknown으로 유지하되 요구된 관측을 생략하지 않는다.
- **악수:** 시간 구간을 무시한 정확한 초 단정, 반대 자료 삭제, 이름만 바꾼 같은 가설 재제출. 자료가 무엇을 반박하는지와 아직 부족한 관측을 보여 준다.
- **필요 계약:** 관측 시간 구간/출처, 경쟁 가설의 관찰 가능한 예측, 가설 정정 이력, 다음 관측 선택. 숨은 culprit ID를 반환하는 check-answer API는 만들지 않는다.

## 7. 아키텍처에 먼저 고정할 최소 요구

| 분야 | 필요한 현재 상태·행동 | 피해야 할 우회 |
|---|---|---|
| 팩/저장 | 팩별 시작 사건·순서·완료·결말·설정/현재 진행 분리, 명시적 팩 선택 | 타편 완료를 필수 선수로 등록, 기존 저장 자동 덮어쓰기 |
| 침투 | actor/object 권한, 실제 경로·서비스, 입력/출력 경계, 제한 위임·자료 동등성 | 정확한 도구 ID/문장/명령 횟수로 완료 |
| 방어 | 정밀 정책·정상 업무 시나리오·공격 시나리오·대체 경로·부분 rollback | 공격 probe만 거부되면 전부 끈 상태도 성공 |
| 관측 | 누가 어디에서 언제 어떤 범위의 결과를 보았는지, 수집 사본과 원본 진실성 구분 | 관측마다 정답 actor/final_claim을 끼워 넣기 |
| 추적 | 후보 edge·지원/반증 관측·미확정 상태·새 관측 선택·정정 이력 | 내부 ground truth를 즉시 정답률·확신 퍼센트로 노출 |
| R01 | 허용 연산/함수의 작은 의사코드, 조건 평가·분기·call trace, 입력 반례 | XOR 한 단어·소스 문구 이름 맞히기 |

아키텍처 초안의 공개 팩 ID는 `intruder`·`defender`·`tracker`다. 기존 저장용 `legacy_intruder`는 별도 이어하기 호환 경로이며 새 플레이의 필수 선수나 네 번째 공개 캠페인이 아니다. 팩별 진행·현재 세계·관측·결말과 명시적 저장 선택을 분리한다.

최소 새 모형은 `response_lab`(정밀 정책을 같은 세계의 정상/위협 요청으로 검사·rollback), `observation_case`(허가 관측·출처 보존·가설과 후속 수집), `branch_vm`(작은 분기·호출 실행)으로 묶는다. 모델명은 도구 버튼 세 개를 더 붙이라는 뜻이 아니다. 터미널·Browser·RequestLab·probe가 같은 세계 dispatcher를 호출하고, 콘텐츠가 정답 fact를 직접 켜서 판정을 대신하지 않는다.

R01의 첫 모델은 `main → format_check → signature_check → release`처럼 4~6개 함수/분기면 충분하다. scope가 부족해도 release되는 반례와 정상 범위에서의 허용 예를 실제 실행 결과로 구분한다. 소스를 읽는 경로와 입력쌍·call trace를 보는 경로를 둘 다 지원한다. 실제 CPU ISA·임의 스크립트 실행은 도입하지 않는다.

개념적 가설 edge는 `claim + supporting_observations + contradicting_observations + status`면 시작할 수 있다. 상태는 supported/contradicted/underdetermined처럼 관측에 근거하며 근거 없는 신뢰도 수치를 만들지 않는다. 전체 범용 그래프 에디터나 실시간 추격 AI를 먼저 만들 필요는 없다.

## 8. 재미·다양성·정확성의 수용 기준

| 검증 | 통과 근거 | 실패 예 |
|---|---|---|
| 반복 제거 | 기존66 exhibit를 없애거나 선택 자료로 내렸고, 메인 완료가 공통5행동×66에 의존하지 않음 | 파일/계정/주소만 바꾼 같은 수집 체인 |
| 판단의 차이 | 카드별로 무엇을 예측하고 어떤 새 결과 때문에 다음 행동이 달라지는지 저자가 설명하고 플레이에서 관찰 | 도구 이름이 다르다는 목록만 제시 |
| 의미 있는 대안 | 서로 다른 경계·관찰·대응으로 같은 상태/업무 결과에 도달하는 두 실행 fixture와 정상/오답 결과 | 같은 도구를 GUI/CLI 두 번 호출한 것을 두 해법으로 셈 |
| 현재 동작 | M24에서 웹/route/service를 각각 바꾸면 관련 현재 조건이 실패하고 해당 경계 재확인 뒤 회복 | 이전 완료 fact나 과거 로그가 현재 폐쇄/권한 부족을 무시 |
| 방어 오탐/롤백 | 전부 끄기 실패, 두 정밀 대응 성공, 부분 rollback으로 잘못된 차단은 복구하되 폐기 자격은 계속 거부 | 임시 격리·전체 원복을 무조건 완전 복구로 표시 |
| 추적 정보 공정성 | **공개 관측을 같게 두고 숨은 행위자만 바꿔도 관측 전 피드백은 동일**; 실제 다른 후속 관측 후에만 지원/반증이 달라짐 | 관측 없이 숨은 이름을 맞히자 즉시 맞음/틀림 출력 |
| 추적 종결 | 요구 연결·출처·반증·후속 관측을 가진 제한적 인계는 허용, 무근거 실명 단정/아무것도 모름은 불충족 | 실명 문자열 일치 또는 모든 unknown이 공짜 완료 |
| 독립 입문 | 침투를 안 한 참가자도 D01/T01의 목표·권한·첫 결과를 이해하고 각 팩 결말까지 진행 | 타편 명령·인물 비밀·세이브를 설명서로 요구 |
| 표면/원리 구분 | 실제 조건·단순화·지원 밖 입력이 구분되고 KO 사람용 설명이 KO로 표시 | XOR=암호 감사, 열린 포트=권한, HTTPS 임의 해독, IP=사람 |

샘플 단계에서는 각 편의 위 두 사건을 먼저 완주 가능한 조합으로 만들고 **한 묶음**으로 검사한다. 현재 코드에 없는 모형을 억지 fact로 우회하지 않는다. 기능 검사 후 사람 관찰에서 접근 획득·통제 회복·새 관측의 적중을 느끼는지, 다음 의뢰/관측을 스스로 선택하려 하는지 확인한다.

사람 관찰은 “성공률이 높으니 재미있다”는 결론이 아니다. 새 결과를 보고 가설/대응을 바꾸는 장면, 같은 세션/문서를 불필요하게 다시 찾는 막힘, 실제로 선택한 대안과 그 이유를 기록한다. 철자·창 전환에 막힌 시간을 퍼즐 난도로 계산하지 않는다. 자동 fixture는 유효 경로 증거이며 사람의 재미·교육 효과 증거가 아니다.

기존 침투 8~12시간 목표와 [480+240분 예산](../PACING_AND_STORY.md)은 유지한다. 반복 수집을 빼서 줄어든 시간을 명령 재입력·강제 대기·필독 문서로 다시 채우지 않는다. 사건의 독립 판단·경계 실험·인물 선택·선택 조사에서 분량을 만들고 실제 플레이 분포로 조정한다. 방어/추적 각8개의 시간은 아직 별도 실측 전이며 침투 예산을 세 팩 합계로 나누지 않는다.

## 9. 다음 집필/구현 인계

1. 아키텍처 담당이 팩 저장·현재 관측·정밀 대응/rollback·가설/후속 관측·작은 분기 모델의 실제 지원 계약을 고정한다.
2. 이 문서의 M05/M24·D01/D07·T01/T07을 계약에 대조해 지원되는 상태/행동/관찰로 표현한다. 새 모델 이름만 붙여 기존 compare 입력을 남기지 않는다.
3. 후속으로 쓰기 범위를 명시받은 뒤 캠페인 JSON·생성기·해법 fixture·한영 집필을 수정한다. 이번 단계는 이 문서 한 파일에 한정한다.
4. 저자와 별도 검토자가 원자료·두 해법·반례·인물 반응을 읽고, 통합 runtime/저장/locale/실제 UI 검사와 사람 플레이를 구분해 보고한다.

현재 확정한 것은 콘텐츠 재설계 제안과 최소 계약 요구다. 새 방어/추적 실행판·재설계된 JSON·시제품·8~12시간 달성을 만들었다고 표시하지 않는다.
