# 심야접속 · 전체 캠페인 콘텐츠 제작 계약

소유 범위는 `godot/data/campaign/`, 콘텐츠 생성 helper, 테스트 전용 해법 fixture다. 24개 메인과 선택 사건 S01·S02·R01·P01을 집필한다. 실행 계약은 같은 폴더의 `campaign-contract.md`와 동기화하며 게임 코어·UI·배포 파일은 여기서 수정하지 않는다.

## 이야기 정본 제안

해람의 ‘연속성 보장’ 이관 작업은 서비스 중단을 줄이지만, 예외로 분류된 시민 접수와 운영 기록을 기록부 밖으로 밀어낸다. 처음에는 외부 침입처럼 보이던 흔적이 오래된 긴급 승인·공유 계정·자동 분류의 결합임이 드러난다. 인간의 책임을 자동화나 한 명의 악역으로 덮지 않는다.

플레이어는 피해를 과시하는 공격자가 아니라 허구망에 들어가 사라질 기록을 회수하고 서로 다른 설명을 대조하는 야간 작업자다. 접속·권한 변화·내부 노드 발견·자료 확보를 성취로 주며, 수정은 복구 의뢰 5개와 선택 후속 활동에서만 요구한다. 회수 사본의 출처와 정상 기능 보존이 모든 경로에 적용된다.

각 사건은 5~8개의 의미 있는 조사/상태 변화 단계를 갖는다. 단계 제목은 안내이고 실제 판정은 확보 자료·입증 사실·정책/서비스 상태·보존 제약으로 정한다. 근거가 의존하는 선행 자료는 필요하지만 특정 도구 경로를 순서대로 따라야 하는 것은 아니다. 아래 A/B는 테스트 fixture에서 실행되는 다른 경로이며 원문 정답 파일은 게임 배포에서 제외한다.

## 집필·문자열·후속 전달

한국어/영어 서사를 분리하고 주소·파일 경로·계정·도구 입력은 언어와 무관한 안정 ID를 쓴다. 미션 제목, 의뢰, 목표, 3단계 요청형 힌트, 선택 해설, 실제 원리/모형/한계, 문서·사이트·대화·후일담을 번역 대상으로 한다. 추가 네 언어는 확정 키 목록으로 인계한다.

각 사건의 선택 문서는 같은 사실을 다시 설명하는 분량 채우기가 아니라 상충하는 주장·인물 사정·다른 진입 단서를 제공한다. 사건의 핵심 사실은 실제 행동 결과와 짧은 대화로 드러나며 모든 선택 문서를 읽어야 완료하지 않는다.

8~12시간은 사용자 플레이 검증 목표다. 타이머·반복 작업·정답 문자열을 통해 하한을 강제하지 않는다. 캠페인 전량·두 경로·언어 키 완성, 런타임 통과, 실제 플레이 시간/재미는 별개의 검증 결과로 보고한다.

## 생성물과 검증 인계

| 파일 | 내용 |
|---|---|
| `godot/data/campaign/campaign.json` | 메인 M01~M24, 선택 S01·S02·R01·P01, 113개 사건별 호스트 정의, 117개 가상 페이지, 190개 Challenge, 3개 근거 기반 결말 |
| `godot/data/campaign/locales/ko.json`, `en.json` | 각 826개 실제 표시 문자열. 주소·계정·명령·canonical 기록과 분리 |
| `godot/data/campaign/content_inventory.json` | 생성물 수·사용 모형 종류와 검증 범위 |
| `godot/data/campaign/locale_revision.json` | 2차 개정의 신규 337·기존 변경 272·미참조 문장 삭제 162키 인계 목록 |
| `godot/tests/fixtures/campaign_solutions.json` | 28사건×2경로의 실행 action과 독립적인 예상 상태/응답. 게임 런타임이 읽는 정답 파일이 아님 |
| `tools/build_campaign_content.py` | 표준 라이브러리만 쓰는 재현 가능한 생성 helper와 구조 assert |

각 사건에 3단계 요청형 힌트·선택 해설·원리/추상화/한계가 있다. 선택 학습·특정 명령을 목표로 강제하지 않는다. 19종 모델에는 idor/auth/session/csrf/upload와 분석·권한·가상 실행·피벗·리버싱·메모리가 포함된다.

2차 개정에서는 M01을 유지하고 66개 독립 근거를 추가했다. M02~04는 선행 근거+핵심 자료, M05~12는 선행 근거+핵심 자료/복구 상태+후속 대조, M13~24는 선행 근거 2개+핵심 자료+후속 해석을 요구한다. M21·22·24는 후속 범위 근거가 하나 더 있어 총 5개 근거가 연결된다. `requires_facts`와 `records.grants_facts`로 양쪽 출처에서 같은 사실을 남긴다. 전체 필수 회수 자료는 89개이며 복구 사건은 그 밖에 실제 차단/정상 관찰 fact도 필요하다.

이는 단계 문장만 늘린 변경이 아니다. 두 현장 원장의 비교나 별도 인증을 거친 보관 원장의 행 분석이 실제 기록과 사실을 생성한다. 앞 근거 없이 핵심 자료를 얻거나 핵심 자료만 얻고 해석·대상 범위를 생략하면 완료되지 않는다. 같은 근거는 현장/독립 보관 중 선택할 수 있고 중간에 경로를 바꿀 수도 있다.

회수·조사 사건의 대안은 다른 인증 노드와 독립된 trace/compare/path/permission 관찰로 같은 근거를 남긴다. M01의 유효 미러 외에는 사이트의 보관 버튼이나 동일한 signed.log 복사로 매 사건을 끝내지 않는다. 복구 5사건의 두 경로는 조사 출처와 조작 채널이 다르지만 동일한 안전 상태를 검증한다. 서로 다른 방어 메커니즘 두 개를 구현했다고 주장하지 않는다. 복구 판정의 secure fact는 자료 사본 회수만으로 발급하지 않는다.

공개 route 파일에서 inspect/retain 계정을 정답처럼 제공하는 방식은 제거했다. 사건별 역할과 다른 인가 값을 의뢰 범위에 맞춰 제공하고 원자료는 역할 소유의 `/desk`에 둔다. 표시 문서는 접수·요청·인계·원장·권한·패킷 관측 형식이며 model/record_id/source/policy_id를 직렬화한 개발 manifest가 아니다. 기록 출처는 실제 확보 경로를 유지하고 후일담이 사용하지 않은 해법을 사용했다고 단정하지 않는다.

M21은 객체 참조의 리드와 뒤 조회를, M22는 서버 피벗과 별도의 관리 세션·실제 목표 파일을 연결한다. M23은 정상 사진·새 세션·정상 로그인 관찰과 443/5050 서비스·폐기 자격 차단·광역 우회 금지를 함께 검사한다. R01은 가상 `verifier.asm`, P01은 가상 `memory.map`을 읽고 작은 모델을 실험한다.

M13은 등록된 `diagnose;inspect:QUEUE13` 두 가상 작업만 연결하며 실제 서비스 계정 worker/inspection과 호출 계정을 구분한다. M17의 XOR는 공급된 허구 후보의 포장 모형이며 비밀번호 해시나 실제 암호 감사 알고리즘이 아님을 원리·한계에 명시했다. M21의 접수 조회와 M23의 개별 업무 검증은 가상 사이트 링크로도 연결된다. 로그인 폼 자체를 로그인한 사용자에게만 보여 주는 순환은 없다.

M01의 `handoff-47` 본문·허용 출처는 기존 첫 플레이와 동일하게 보존했다. 언어 변경은 키 표시만 바꾸고 기록 ID·본문 무결성·가상 경로·인증 값에는 영향을 주지 않는다. 나머지 네 언어와 런타임 PO는 번역 담당의 파일이며 이 helper는 덮어쓰지 않는다.

`character_events`는 네 배역의 등장·얼굴 공개 조건을 전달한다. C01/C03의 얼굴 공개는 선택이며 메인 완료·자료·권한 조건과 분리한다. 실제 얼굴 이미지·UI 선택·저장 복원은 presentation/runtime 담당이 연결한다. 결말은 전체 발견 사실에 따라 공개/독립 검증 선택이 달라지고 기본 봉인 감사는 선택 사건 없이도 가능하다.

부가 결말은 선택 사건의 첫 자료만으로 후속 해석을 확인했다고 말하지 않는다. 공개 기록은 `s01_exhibit_2`, 독립 검증 보관은 `s02_exhibit_2`·`r01_exhibit_2`·`p01_exhibit_2`까지 요구한다. 결말 대사와 기본 봉인 감사의 조건은 유지한다.

원본 보존 전용 템플릿을 쓰는 조건을 제외한 200개 목표에는 기존 번역 키의 `label_display`와 공개 가상 주소의 `target_display`를 붙였다. 증거 제목·업무 표제·계정/도메인/포트로 표시하고 raw fact/policy ID는 표시 이름으로 사용하지 않는다. UI의 `display_name`은 이 표시 메타를 해석하고, 판정은 계속 기존 kind/id/value를 사용한다. 메타 추가 전후 비교에서 826개 한영 문자열·해법 fixture·canonical 자료·원래 미션 조건이 동일함을 확인했다.

생성 helper의 28개 ID·두 경로·단계 수·기록 본문·출처·부모 경로 검사를 통과했다. 추가 정적 대조에서 ko/en 키 일치·노드 연결·계정·정책·IDOR 객체 출처, fixture의 로그인 자격과 읽기 경로 존재를 확인했다. M05 이후 경로는 대체로 14~33개의 실제 API action을 갖는다. 액션 수와 읽기 분량은 제작량 자료이며 플레이 시간 보증이 아니다. 패킷 rows의 `body`는 번역 키가 아니라 canonical 관찰 데이터다. 이 검사는 실제 게임 56경로 재생이나 사람 플레이 시간의 증거가 아니다.

첫 backend에서 드러난 누락 미션 schema와 잘못된 B 진입 순서를 데이터 계약에 맞춰 교정했다. B는 기존 primary gateway에 먼저 인증하고 custody에 진입한다. M15·17·22는 제한 대상에서 관측 원장으로 바로 뛰지 않고 원래 gateway로 돌아와 후속 근거를 얻은 뒤 대상 세션을 재확인한다. 라우팅을 넓혀 우회하지 않았으며 생성 helper는 56경로의 모든 SSH가 선언된 직접 간선을 사용하는지와 세션 exit 균형을 검사한다. 실제 전체 runtime 재생 결과는 root 검증 기록에 남긴다.

전체 런타임·저장·UI·배포 검증은 root 통합 묶음으로 실행한다. 테스트 fixture의 export 제외는 export preset/gate 담당이 확인해야 하며, 아직 측정하지 않은 플레이 시간을 8~12시간 달성으로 쓰지 않는다.
