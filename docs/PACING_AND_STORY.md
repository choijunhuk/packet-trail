# 8~12시간 플레이타임·스토리·선택 사건 설계

**사용자 확정 목표: 빠르게 핵심을 진행하는 첫 플레이 약 8시간, 탐색과 이야기를 충분히 즐기면 약 12시간.** 아래 분량은 목표를 만들기 위한 설계 예산이며 실측이 아니다. 숙련자의 속도 공략·대사 건너뛰기·독창적인 우회로 8시간보다 짧아질 수 있다. 이를 막으려고 강제 대기나 반복 작업을 넣지 않는다.

## 1. 분량을 어떻게 만들 것인가

권고 콘텐츠는 **6장·메인 사건 24개+선택 사건 4개**다. 메인 기술 목록은 [CURRICULUM.md](CURRICULUM.md)를 유지하면서, 주요 사건을 여러 대상·이해관계·유효한 진입 경로를 가진 사건으로 깊게 만든다.

| 빠른 첫 플레이 구성 | 설계 예산 |
|---|---:|
| 짧은 도입 사건 8개 × 약 10분 | 80분 |
| 일반 사건 10개 × 약 19분 | 190분 |
| 장말 연쇄 사건 6개 × 약 20분 | 120분 |
| 메인 브리핑·인물 대화·후일담 | 55분 |
| 프롤로그·엔딩 | 20분 |
| 최초 작업실·OS 적응·사건 전환 | 15분 |
| **합계** | **480분 ≈ 8시간** |

사건 24개 분류의 내부 계산은 8+10+6이다. 장말 연쇄 사건은 M04·M08·M12·M16·M20·M24를 기본 후보로 둔다. 실제로 난도가 높은 M21·M22 등은 일반 사건의 깊이를 조정해 균형을 맞춘다. 브리핑·후일담 시간을 사건 조작 시간에 중복 합산하지 않는다.

| 충분히 탐색하는 플레이의 추가 구성 | 설계 예산 |
|---|---:|
| 선택 사건 4개 × 약 20분 | 80분 |
| 선택 메일·웹 문서·인물 기록·증거 연결 | 60분 |
| 대안 경로 조사·추가 가설 실험 | 60분 |
| 선택 복습·전이 도전 | 20분 |
| 작업실·음악·선택 대화 | 20분 |
| **추가 합계** | **240분 ≈ 4시간** |

이 시간은 자동 확보되지 않는다. 선택 사건을 무시한 사람이 필수 조사에서 막힌 시간을 ‘탐색 콘텐츠’라고 세지 않는다. 선택 기록은 메인 정답을 숨겨둔 의무 문서가 아니라 이야기·대안 해법·인물 이해를 넓히는 자료다.

## 2. 사건을 깊게 만드는 방법

기술 한 개를 알려주는 짧은 실습만 24개 나열하면 8시간을 자연스럽게 채우기 어렵다. 일반 사건은 ‘문제 징후→후보 대상 비교→진입 경로 선택→필요한 권한/내부 경로 조사→목표 확인→제약 검증’ 중 필요한 단계를 연결한다.

예를 들어 M05에서 단순히 객체 번호만 바꾸는 것으로 끝내지 않는다. 어떤 두 계정을 비교할지 단서를 찾고, 자료가 서버 어디에서 제공되는지 확인하며, 다른 서비스 기록으로도 같은 문제를 입증할 수 있게 만든다. 회수된 자료가 맞는지와 사건의 보존 조건을 확인한다. 조치 후 재검증은 복구 의뢰나 선택 후속 연습에서 다룬다. 새 이론을 한꺼번에 늘리기보다 이미 배운 브라우저·로그·파일·요청 도구를 재사용한다.

장말 사건은 여러 짧은 하위 목표를 연결하되 60분짜리 막힘으로 만들지 않는다. 중간 체크포인트와 재개를 제공하고 이미 확인한 사실을 반복 입력시키지 않는다. 지도·노트·요청 저장으로 정신적 부담을 줄인다.

## 3. 장별 서사 구조

| 장 | 사건 규모·서사 역할 | 플레이 감정 | 재사용·조합 |
|---|---|---|---|
| 1 | 서윤의 인계 기록 회수 의뢰가 다른 서버로 이어짐 | 첫 접근의 성취→새 연결→의문 | 접속·파일·스캔·요청 |
| 2 | 자료의 실제 주인을 추적하며 숨은 관계 발견 | 접근권 확장·신뢰와 의심 | 요청·로그·객체·세션 |
| 3 | 입력과 자료 처리에 연결된 의도적/비의도적 결함 | 실험·추론·반전 | 웹 도구와 파일·권한 |
| 4 | 외부 웹 문제에서 내부 서버로 이어지는 경로 | 침투감·위험 관리 | 경로·피벗·서비스·권한 |
| 5 | 모순된 기록과 숨은 자격 정보로 사건 재구성 | 확신 흔들림→근거 수집 | 패킷·로그·파일·후보 분석 |
| 6 | 최종 기록을 회수하고 전달 대상을 선택 | 자율 판단·종합·결말 | 도구를 스스로 선택 |

도시 ‘해람’과 인물 이름은 초안이다. 익명 연락처 서윤은 첫 회수 의뢰와 도구의 쓰임을 제공하지만 의도는 감춘다. 동료 도윤은 앞서 얻은 자료를 해석하며 다음 서버의 맥락을 더하고, 외부 제보자는 두 사람의 설명과 충돌하는 기록을 제시한다. 조연을 늘리는 것보다 같은 인물이 이전 조치에 반응하도록 만든다. [캐릭터 아트 문서](CHARACTER_ART.md)의 민서·태경은 추가 배역 후보이며, 채택 전에는 메인 스토리의 확정 인원이나 자산 제작 의무로 계산하지 않는다.

배신·음모는 오래 읽어야만 알 수 있는 문서 뒤에 모두 숨기지 않는다. 핵심 사건은 행동과 서비스 상태에서 드러나고 선택 기록이 해석을 풍부하게 한다. 결말의 차이는 실제로 발견한 사실과 보고·조치 선택을 반영한다.

## 4. 선택 사건 4개

| ID | 제안 사건 | 핵심 경험 | 재사용 기반 |
|---|---|---|---|
| S01 | 지워진 인계 공지 | 사이트·메일·문서 간 모순을 찾아 제보 출처 검증 | Browser·검색·파일·로그 |
| S02 | 두 번 전달된 신호 | 서로 다른 관찰 지점의 통신·로그를 연결 | PacketLens·LogLens·경로 |
| S03 | 잠긴 보관함 | 허구 후보·해시·권한 정책을 비교해 필요한 자료 확보 | CredAudit·FileLens·AccessView |
| S04 | 다른 길의 증인 | 이미 해결한 사건을 다른 유효 경로로 입증 | 저장 요청·대안 접근·증거 정책 |

S01~S04는 12시간형 탐색 콘텐츠를 확보하는 기본 제작 목표다. R01 리버싱·P01 포너블 시제품이 기준을 통과하면 선택 사건 일부를 교체하거나 추가하는 식으로 조정한다. 별도 시스템 두 개를 무조건 더해 일정을 늘리지 않는다.

## 5. 학습과 자유도의 균형

튜토리얼에서 보여준 경로는 첫 풀이의 한 예다. 숙련자가 다른 방식으로 목표와 제약을 충족하면 진행한다. 따라 하지 않은 기술은 미평가로 두고 복습 공간에서 선택할 수 있게 한다.

일반 사건마다 새 개념 하나에 집중하되 이미 아는 기술 1~2개를 자연스럽게 요구하는 상황을 만든다. 원인 설명 퀴즈·특정 명령 사용·증거 핀을 강제해 플레이 시간을 늘리지 않는다. 기법 이름을 알려주지 않는 후반 사건에서 스스로 도구를 고르는 재미를 검증한다.

## 6. 플레이타임 측정·조정

시간은 능동 조작·읽기·선택 대화·선택 사건·대기/막힘·자리 비움으로 구분한다. 배속 테스트나 개발자의 정답 재생 기록으로 사용자 8시간을 추정하지 않는다.

1. 시제품에서 초보자·관련 경험자·숙련자 그룹을 구분해 완주·막힘·선택 탐색을 관찰한다.
2. MVP에서 사건당 실제 조사량·대안 경로·읽기량과 이탈 지점을 확인한다.
3. 전체 초안 캠페인에서 빠른 첫 플레이 약 8시간, 충분한 탐색 약 12시간이 자연스럽게 나오는지 검증한다.
4. 짧으면 새 의미 있는 조사·분기·이야기를 추가한다. 길면 중복 입력·되풀이 설명·답 없는 막힘을 줄인다.
5. 속도 공략이 짧아졌다는 이유로 대안 풀이를 막거나 타이머를 늘리지 않는다.

표본 수·실측 분포·미완주 사례를 함께 보고한다. 목표에 맞는 사례만 골라 평균을 맞추지 않는다. 최신 구현·실측 상태는 [README](../README.md#현재-상태)에 모은다.
